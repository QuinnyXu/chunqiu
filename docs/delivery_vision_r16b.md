## 二、交会检测如何对齐 fixtures 三条护栏

检测器（`detectMeetings`）：
- **a 级 · 同场**＝同一 `event_id`、双方皆亲至、事件有 `place_id` →「同场（同一记载）」。
- **b 级 · 同年同地**＝不同 `event_id`、同 `place_id`、双方皆亲至、`|Δyear| ≤ 1`。

三条护栏（Sophia 核查产出，逐条落实）：
1. **生死过滤以 person 生卒年为准**（`personParts`）：`presence=相关` 一律排除；再按 `people.death_year_bce` / `birth_year_bce` 过滤——事件年 > 卒年（追叙）或 < 生年（未生）者不计。故「子文卒后被追叙」（R5）、「申舟卒于前595而围宋系前594」（R4）均不检出。
2. **跨年事件容忍 ±1 年**：b 级用 `|Δyear| ≤ 1`（护栏②）；命中 `Δyear==1` 者在交会卡与弹卡上注明「跨年事件，在场判断已容忍 ±1 年（前X / 前Y）」。同地但相差多年者（R3 郢都相差 13 年）自然落在 ±1 之外，不检出。
3. **同链→「相邻记载」**：`sameChain` 判两事是否共享 `source_id` 或 `event_id` 数字相邻；是则徽标用「相邻记载」，否则「可能相遇（同城未必同时）」。现库 4 处 b 级全部 `chain=true`→全标「相邻记载」，与 fixtures「本库无独立偶合」的结论一致；真正的独立偶合待数据增长后自然以「可能相遇」出现。

**免责主张**采用 B3 样板句一字不差：「同城未必同时，不能仅据同年同地断定相遇。」——常驻交会侧栏顶部（`.cmp-disclaimer`），交会弹卡内再重复一句（`.cmp-disclaimer.in-card`）。

## 七、验收偏差上报

- **「复用现有播放引擎」的解读**：现有单人 `play` 引擎为「按段长距离驱动」，与并观所需「按绝对年驱动·双标记·b 级自动暂停」语义根本不同，无法原样套用。按「勿重写现有引擎」的口径，**未改动 `play/*` 一字**，另建 `cplay`（按年驱动），**复用 `easeInOut` 缓动**及 RAF/字幕/暂停/续播的结构与交互约定，不另造缓动或计时框架。此为对「复用引擎」的忠实折中，特此报备。
- **生卒数据**：多数主角 `birth_year_bce` 留空、`active_years_bce` 为自由文本。年轴生卒刻度与灰置在缺结构化生卒时，以 `active_years_bce` 的「前N」与其事件年兜底，并把刻度标注为「活跃自/止」（非「生/卒」），如实区分，不臆造精确生卒。此为呈现层派生，未改数据。

## 八、两播放引擎手感核对（r16 承接领队裁定）

背景：领队裁定 cplay 偏差有条件批准、MVP 照此上线，但要求本轮核对 `play`（单人，距离驱动）与 `cplay`（并观，按年驱动）在缓动/暂停/终点归位三项手感一致。**本轮为核对＋补文档，未改任何播放功能行为（`play/*`、`cplay/*` 代码零改动）。** 逐项结论如下：

| 项 | 结论 | 依据 |
|---|---|---|
| 缓动曲线 | **一致** | 二者调用同一无状态叶子 `easeInOut(u)`（app.js:1625），均作用于「分段的归一化进度 u」，产生逐段缓入缓出的同一手感。 |
| 暂停语义 | **核心一致** | 二者同为「`cancelAnimationFrame` + `paused=true`」冻结、续播用 `startTs = performance.now() - elapsed` 停表补偿（play:1657-1662 / cplay:2465-2471）。 |
| 终点归位 | **语义等效** | 播完后标记停在各自轨迹末站、保持可见、按钮复位可重播。 |

**逐项写实说明（含实现路径差异及为何不强改）：**

1. **缓动**：`easeInOut` 是纯函数、无播放状态，两引擎直接共用同一份。差异仅在「段」的定义——单人按相邻站点的**几何距离** `L` 分配段时长（play:1683-1695），并观按相邻轨点的**年份跨度**分配（year 线性于时间，cmpMarkerPos 按 `(year-y0)/(y1-y0)` 插值，app.js:2137）。这属于「段」的结构定义差异，**不改变缓动曲线形状**，读者感知到的「起步慢—到站慢」手感一致。无需对齐。

2. **暂停**：停表机制逐字对应，续播补偿公式相同。唯一表现差异是**暂停时字幕的去留**——单人 `hideCaption()` 令到站字幕淡出（play:1654），续播时按 `lastStation` 复播（play:1661）；并观暂停时保留 `#cmp-caption`。此差异源于两条字幕的**语义不同**：单人字幕是「第 N/几 站」到站播报（暂停即无「站」可报，淡出合理）；并观字幕是「当前年份 · 甲乙在世态」的年份指示器（暂停时读者正欲读此信息，保留更合理，且续播首帧 `cmpUpdateAt` 会自然重画）。故此差异是按各自字幕语义的**有意区分，非不一致**，不强改（改则反而削弱并观暂停时的年份可读性）。

3. **终点归位**：结果等效，实现路径不同——
   - 单人 `finishPlayback`（play:1743-1747）**显式**把 marker 坐标 set 到 `traj[末]`，强制落位。
   - 并观 `cmpFinish`（2529-2534）不显式落位，而是靠 `cmpStep` 最后一帧先执行 `cmpUpdateAt(year)` 再判 finish（2518-2519）：末帧 `elapsed>=dur` 时 `cmpYearNow` 的 u 被钳到 1，`year` 精确等于 `axisMax`；而 `axisMax = max(hiA,hiB)+1`（app.js:1970）对任一人恒 `≥ 该人 lifeSpan.hi ≥ 其轨迹末点年`，`cmpMarkerPos` 遂走 `year>=last.year` 分支（app.js:2132）把两标记各自落在己轨末站。故**隐式落位可靠且与单人等效**。
   - 为何不强改为显式：并观的落位嵌在「年→双标记」映射里，末帧 `axisMax` 覆盖两轨末点是其数学不变量（非偶然），另加一次显式 set 属冗余、且会绕过既有的年驱动路径。领队要求「不改功能行为」，故保留隐式落位，仅在此写实登记其成立条件，供将来合并时校验。

**综上**：三项手感在读者感知层一致（缓动同曲线、暂停同停表法、终点同落位结果），无实质会被读者感知为「手感不同」的偏差，**本轮未做对齐改动**；两处实现路径差异（暂停字幕去留、终点显式 vs 隐式落位）已如实记录，均为「结果等效、改动无收益且触碰 `play/*` 或并观语义」而保留。

## 九、为何无法复用（play → cplay）：结构差异

核心一句：**可复用的是无状态叶子与交互约定，无法复用的是播放状态机本身。** 两引擎的状态模型在结构层不同构：

| 维度 | 单人 `play`（距离驱动·单轨单标记） | 并观 `cplay`（按年驱动·双轨双标记） |
|---|---|---|
| 驱动量 | 沿单轨的**累计几何距离**（`segs` 按 `L=hypot(Δx,Δy)` 分配时长，play:1683-1695） | **绝对年**（`cmpYearNow`：year 线性于 elapsed，从 `axisMin` 推至 `axisMax`，2431-2434） |
| 标记数 | 1 个 `#play-marker`，索引即站序 | 2 个 `markerA/markerB`，**各沿己轨**由同一 year 分别插值（trajA/trajB 长度、年份点、生卒区间彼此独立，2436-2437） |
| 「段」定义 | 相邻**站点**（同点已聚合），段时长 ∝ 空间距离 | 相邻**轨点年**，段时长 ∝ 年份跨度 |
| 时间轴 | 无绝对年轴；进度是一维距离比例 | 绝对年轴 + 游标 `#cmp-playhead`／年号 `#cmp-playyear` 随 year 移动（2438-2444） |
| 生卒态 | 无此维度 | year<生年→未生、>卒年→已卒，字幕逐人标注「未生/在世/已卒」（灰置，2450-2455） |
| 中断语义 | 无 | **b 级交会年自动暂停一拍**：跨过共享年时 `holdUntil` 冻结 1.2s、脉冲高亮交会点、字幕换免责句（2498-2516）——「共享年」是双人独有概念，单轨无从谈起 |
| 私有状态字段 | `segs / lastStation / elapsed` | 额外需 `lastYear / fired / holdUntil / dur(按年跨度算)`，play 全无 |

**结论**：`play` 的状态围绕「单标记沿单轨的一维距离进度」，其 `segs`、`lastStation`、`announceStation` 皆服务于站序推进；`cplay` 的状态是「一条绝对年时间轴 + 两条独立轨迹的 year→位置映射 + 双人共享年的中断」。将 `play` 泛化成 `cplay` 等于把「距离驱动单标记」重写为「年驱动 N 标记 + 年事件中断 + 生卒态 + 年轴游标」，改动面 ≈ 重写。故本轮另建 `cplay`，**仅复用无状态叶子 `easeInOut`（纯缓动）与三条交互约定**（RAF 循环骨架、字幕 show/hide、`startTs=now-elapsed` 停表续播），未触碰 `play/*`。这正是「复用现有播放引擎」在结构约束下的忠实边界。

**将来合并方向（供下一次触碰播放功能的轮次参考）**：可把 year/distance 抽象为统一的「归一化时间轴 t∈[0,1] → 若干标记的位置」接口，标记数、段定义、中断事件列表作为参数注入；`easeInOut`、停表续播、字幕收发可下沉为共用骨架。单标记单轨是 N=1、中断列表为空、段按距离的特例。合并须在同一轮内完成 play 与 cplay 双向回归（单人到站播报、并观 b 级自动暂停/生卒灰置/双标记末站落位），不可只改一侧。

## 十、技术债登记

**TD-r16-01｜play/cplay 双播放引擎并存**（登记于本节，2026-07-21，Vision r16 承接领队裁定）：
当前存在两套并行的轨迹播放状态机——`play/*`（单人·距离驱动，app.js:1623-1763）与 `cplay/*`（并观·按年驱动，app.js:2429-2541），仅共用叶子 `easeInOut` 与交互约定，状态机本身各写一份（差异见「九」）。三项手感已核对为读者感知层一致（见「八」），MVP 阶段可接受并存。**约束：下一次任何触碰播放功能的轮次，必须先把两者合并为一（合并方向见「九」末段），不得在双引擎上继续叠加新功能。** 合并前每次改动播放行为都需两侧同步核对，维护成本随功能增长而放大——此即登记为技术债的原因。
