### 3.1 主证 · 去注释后逐字节相同（sha256）

**判据**：JS 注释与 CSS 注释都不参与执行／不进入 CSSOM，这是**语言级保证**。故两版文件剥掉注释后完全相同，则改动必然全部落在注释内。

| `site/app.js` | 4545 / 4545 | **0** | `1bf05aa81e3e3c2d3e9f7769b238134aaf18bb9edcadda42f20aec5999a0ad16` |
| `site/styles.css` | 2006 / 2006 | **0** | `3b8b9f10b88c700b827df48edebae78d6b442540d4759159dd3eb35655e679b7` |

（`app.js` 的哈希与 r35 所记同值——本该如此：r35 之后到本件之前，`app.js` 的可执行代码一行未动。这是一条**跨轮的旁证**，不是引用。）

### 3.2 旁证 · 长度守恒（本轮改进了算法，见下）

**r35 的旁证在本轮对不上，原因已查清并修正。** r35 用「被剥字符数」作对账，而该数只计**与原字符不同**的位置——注释内原本就是空格的字符不计入。本轮多处改写改变了注释内的空格数（如 `styles.css` 删去括号时连带删去其前的对齐空格），于是 `app.js` 出现「总长 Δ−45、被剥字符 Δ−26」这种看似不守恒的读数。**这不是改动越界，是旁证的量具选错了**——如实记此，并换量具重证。

**处置：换成精确的注释跨度计法**——把剥离器的填充字符由空格改为一个源文件中绝不出现的哨兵字符 U+0001（`strip_marker_js.js`／`strip_marker_css.js`，scratchpad 一次性工具），则计数即**注释跨度内的全部字符**（不计换行），空格再多也一个不漏。本轮实测：

| 文件 | 总长 改前→改后（Δ） | 注释跨度字符 改前→改后（Δ） | 换行数 Δ | 守恒 |
|---|---|---|---|---|
| `site/app.js` | 219744 → 219699（**−45**） | 32328 → 32283（**−45**） | 0 | **Δ 相等 ★** |
| `site/styles.css` | 68877 → 68809（**−68**） | 9550 → 9482（**−68**） | 0 | **Δ 相等 ★** |

**即：文件长度的净变化，与注释内字符的净变化，逐字符抵消**——注释之外一个字符也没动。

### 3.3 `styles.css` 的另证：为何不能套 JS 模式，以及引擎级佐证

**CSS 词法与 JS 不是一回事**，r35 的 `js` 模式套用于 CSS 会**吃掉真代码**。本轮写了一支 CSS 专用扫描器（`strip_css.js`：只认块注释 `/* */`，另识别单／双引号串与 `url()` 无引号记法），并用一份**词法陷阱 fixture** 当场对照两支扫描器：

```
输入：  .a { background: url(http://example.com/bg.png) no-repeat; }
CSS 模式输出： .a { background: url(http://example.com/bg.png) no-repeat; }   ← 完好
JS  模式输出： .a { background: url(http:                                     ← 后半行被当行注释吞掉
```

同 fixture 另含 `content: "/* 这不是注释，是字符串内容 */"` 与 `url("https://…")`，CSS 模式均原样保留、只剥掉真注释（被剥 17 字符）；JS 模式被剥 49 字符（多吃的 32 字符即那半行代码）。**这就是「另证」而非「复用」的实据。**

**引擎级佐证（不依赖我手写的扫描器）**：把每份 `.css` 交给 Chromium 的 CSS 解析器，取解析后 CSSOM 全量规则的递归 `cssText` 序列化求 sha256——**注释在词法阶段即被解析器丢弃，CSSOM 里根本不存在注释这种东西**。四份实测：

| 输入 | CSSOM 规则数 | sha256 |
|---|---|---|
| `styles.css` 改前 | 549 | `2f9ceb25123145cc9e3bb1da6772b98d14696bd4ca20de2c77d5437d85bc0345` |
| `styles.css` 改后 | 549 | 同上 |
| 改前之去注释产物 | 549 | 同上 |
| 改后之去注释产物 | 549 | 同上 |

第一、二行相同 ＝ **浏览器实际应用的样式逐字节一致**（比我的扫描器更有力，因为它就是引擎本身）；第三、四行 ＝ **扫描器自证**（若它吃掉了真 CSS，去注释产物的 CSSOM 必与原文不同）——这是 CSS 的 `node --check` 等价物。

### 3.4 工具自证 · `node --check`

`app.js` 改前、改后两份**去注释产物**分别跑 `node --check`，**均通过**。扫描器若误吞代码，语法必坏。
