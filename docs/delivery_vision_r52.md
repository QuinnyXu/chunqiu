## 三、甲之改：`site/styles.css` `.event .role-chip`

nowrap 令该 flex 项之 min-content ＝ max-content，而 flex 项之**自动最小尺寸**取 min-content，于是「缩不下去」——只要值之自然宽超过可用宽，**必然**溢出，与字数无关。三行治之，一行一事：

| 行 | 所治 |
|---|---|
| `white-space: normal` | 撤 nowrap。汉字本可逐字断行，撤后 min-content 归于一字之宽，项遂缩得下去；**且不改任何「本就放得下」之值之排版**（同串 max-content 宽与 nowrap 时相同） |
| `overflow-wrap: anywhere` | 为串内无处可断者（`` `Q492` `` 一类拉丁记号）留退路，不留「一个长词撑破」之口子 |
| `max-width: 100%` | 自成一行时之硬闸。依 CSS Flexbox §4.5，确定之 max-main-size 会把自动最小尺寸一并钳住，故**任意长度之值皆不逾容器**——「不以字数为上界」即在此行 |

- ⚠ **不取 `text-overflow: ellipsis`**：截字之事已在 DOM 层依句读办妥，CSS 再截一刀只会把已裁好的短语又截一次，截在何处不可预期，且读屏器仍读全串。
- ⚠ **不设 `line-height`**：设之即改单行胶囊盒高，叔向「盒矩形逐位相同」之证当场失守。
- 窄屏 `:1999` `.event .role-chip { margin-left: 0 }` **一字未动**。（曾试加 `flex: 1 1 100%` 令窄屏胶囊占满行宽，**当场撤回**——那会把 591 个短值之胶囊在手机上一律拉成通栏，是越界之改，不在本件所治之内。）
