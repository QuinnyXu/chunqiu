## 一、一句话

r24a 走查上报的那个缺口，本轮合上了：**库里有、站上看不见的 13 条事件，现在人人可达**——其中包括「崔杼弑其君」与弭兵之会。

## 二、缺口是什么（本轮的起点）

在此之前，全站呈现事件的**唯一**结构是「主角时间线」。一条事件若不挂任何主角，就同时被三条通路关在门外：

1. 不入任何时间线（时间线按 `personEvents(pid)` 组织）；
2. 被全站搜索索引**显式跳过**（`buildSearchIndex` 里一行 `if (!protoForEvent(e.id)) continue;`）；
3. 资料库无事件页（`LIB_TABS` 只有 background/archaeology/sources）。

r24a 实测该缺口已实存 **13 条**：`E021 / E059 / E077 / E078 / E081 / E184 / E200–E206`。其中不乏史上最著名的条目——**E205 齐太史书「崔杼弑其君」**（兄弟继死其职、南史氏执简以往）、**E206 弭兵之会**。

**这不是数据缺陷，是呈现结构的缺陷。** 那行 `continue` 在写下时是合理的：事件当时没有自己的落点，无宿主者搜出来也无处可去。问题在于「事件只是人物线的附属」这个前提，随着 r23b 时代骨干批入库已经不成立了。

## 三、做了什么

### 3.1 新视图「编年」（hash `#/chronicle`）

**位置**：主导航居「关系」与「资料库」之间——关系是人的网，编年是事的轴，二者同为跨人物的全局视图；资料库属文献层，故排其后。

**每行一事**：年份（`前XXX` ＋鲁君纪年·季月小字）· 分类图标 · **国色签** · 标题 · 展开提示。同年之内依 `sort_key`；全表排序走全站同一个 `evtCompare` ＝ `(year_bce, sort_key, id)`，不另立口径（回归门以 JS 现算序列逐条比对，190 条全同）。

同年续条的年份**淡置**（`opacity .5`）作「同上」解——年份仍在每一行（每行都能独立读），只是不再抢第二次注意力。

**行高取舍**：时间线的「原文 ▾」提示自成一行落右下角；编年把它收回同一行末。190 行若每行都多一行提示，表身平白高出一倍，扫读的便利就折在这里了。窄屏行内已挤，提示回落次行。

### 3.2 国色签 —— 国色的第三种用法

签色取**事发地所属国**（`places.state`）的国色，签文一律**照显 `state` 字段原文**。

- **不破国色制**：`design_notes` §2.0 说「国色定色」，此前它只答「这个人属哪一国」；编年令同一套色也答「这件事发生在哪一国」。两处**同色同义**（都是「国」），不消耗任何新色额度。
- **复合地名不简化**：库内有「齐鲁间」「晋/秦晋间」「周畿内」「申/楚」「郑/鲁」等 8 种复合写法，**签文照显原文**（读者见「齐鲁间」即知其为边地），只在**取色与筛选归组**时按字符序取首个可识别的九国色家族名。这是显示与归组两分：**本站不替史料决定「这地究竟属谁」。**
- **中性签两种**：无 `place_id` 者签「无地望」（现库 7 条）；有地望而其国未立国色家族者（周/曹/邢/蔡/莒…，现库 23 条）照显国名、作中性虚线签——**中性只表「本站未为其立色」，不表「不知其国」。**
- **视图内 `--theme` 归暖赭**：`--theme` 承载当前人物语境色，读者从某人物页进编年时它仍是该国国色，会让整张全局年表染上与本表无关的一国之色。故 `#view-chronicle { --theme: var(--ochre); }`，逐行国别一律交给国色签——**色只答一件事**。

### 3.3 事件卡组件收敛为单一实现

抽出 `eventChipsNode` / `eventQuotesFrag` / `eventBodyNode`，时间线与编年**同源**。chips、摘要、引文分层徽标（§3.5）、编者层标（§3.6）、出处脚注一字不差。

视图差异只有两处，由 `opts` **显式**传入，函数内不猜自己身在何视图：

| opts | 出现在 | 理由 |
|---|---|---|
| `personal` | 人物时间线 | presence 是「**此人**与此事」的关系，不是事件自身的属性；编年无人物语境，故不出此 chip |
| `people` | 编年 | 编年须自己交代「事系何人」，并由此把读者送回人物线 |

**为什么不各写一份**：两份实现必然分叉，分叉之后「哪个才是规格」就没人答得上来。r24a-fix2 的教训（同一件事两处各写各的）已经付过一次学费。

### 3.4 所系人物徽记签

主角带徽记（国色制下徽记是**唯一**逐人通道）、着其国色，点开 → **其时间线并定位到同一条事件**（往返精确到事，不只到人）；非主角无时间线，点开 → 其 ego 关系图。

`presence` 守 conventions §6「相关＝**史文无其在场明文**」的分寸：「相关」作**虚线空心签**，与地图空心点、时间线 presence 标签同一套语汇；tooltip 写「相关：史文无其在场明文」，一律不写成或暗示「其人不在场」。

E205 的崔杼与齐庄公皆标「相关」——合 conventions v1.22「死者不作亲至」通例（庄公为所书之「其君」，已死；崔杼杀书者而其地无明文）。回归门对此单立一条断言，防日后有人「顺手改成亲至」。

### 3.5 搜索接入

- **索引扩至全库**：事件组 **190/190**、原文组 **280/280**，取消「无主角挂链即跳过」。
- **事件与原文两组一律直达编年**并落锚其年：目标行展开＋朱砂描边一闪，**同年诸条一并加年锚标**（暖赭内线），状态行报出「已落锚 前548 · 鲁襄公二十五年（该年 5 条）」。
- **`protoForEvent` 退役**。它存在的唯一理由是「事件没有自己的落点，须临时挑一位主角当宿主」，而挑法本身只能是猜（人物语境优先、否则主角序中首个亲至者）。落点既立，这道猜测不再需要，语义归位为——**事件属于编年，人物线是它的一个视角**。

  **这是一处语义改制，须记明**：190 条事件的搜索落点从「某位主角的时间线」改为「编年」。回人物线的路由不减反增（所系人物签一点即到，且定位到同一条事件）。若领队认为**有主角挂链者仍应落其时间线**，改动面是 `goSearchEvent` 一个函数、可回退到按 `protoForEvent` 分流——但那会带回「这条事件归谁」的猜测，且同一组搜索结果会有两种落点语义。本轮按任务书「命中跳编年视图并落锚该年」的字面执行，此处留痕候裁。

### 3.6 轻筛选（一期从简）

按国、按分类各一组 chips，沿用 `.chip` 胶囊形制。**组内取并集、组间取交集**；计数一律按全库算（不随当前筛选跳变，读者始终看得见全局分布）。

- 交集可以筛空（如「陈 × 婚嫁」＝0 条），故**空表须自己说话**：「此组合下库中无事件——松开一两个条件试试。」不留白屏。
- **筛选不入 hash**（内存浏览态）——分享出去的 `#/chronicle` 一律是全表。
- **搜索落锚优先于筛选**：落锚前先清筛选，否则搜来的事件可能恰被当前筛选挡在表外，读者只会看到一张空表。
- **年段滑块一期不做**（任务书明示），记入候选池。

### 3.7 入口与文案

- 主导航「编年」。
- 关于页「初识春秋」（导览）一句：不想先择一人，也可入编年——并点名齐太史「崔杼弑其君」与弭兵之会两条。
- 关于页「这是什么」一句：**人物线是取景，编年是全景，同一条事件在两处同形呈现，只是入口不同。**

## 四、hash 形态 —— 一处与任务书的偏差（已两头兼顾）

任务书写 `#view=chronicle`。本站自 r10 导航分层起一律 `#/<view>`（`#/relations`、`#/about`、`#/library`），`#view=…` 是 r10 之前的旧形态，会被 `legacyToNewHash` 拦截改写。

**处置**：规范形态定为 **`#/chronicle`**（与既有全局视图一致，站内链接与分享一律用它）；同时把 `chronicle` 并入旧格式白名单——**`#view=chronicle` 照旧可用**，会被就地 `replaceState` 改写为 `#/chronicle`。两种写法都通，任务书字面亦不落空。回归门对两条路径各有一项断言。

## 五、顺带修正：搜索直达的落锚滚动，一次也没执行过

**这不是本轮引入的缺陷，是本轮实测才发现的。** 已按「修正＋声明＋可回退」处理，**单独成一批提交**（`625ff0f`），可独立回退。

**现象**（实测，非推断）：hash 导航之后、在**同一帧**内发起的程序化平滑滚动一次也不会执行——采样 `scrollY` 每 80ms，**全程恒 0**，滚动动画根本没起步；对照同一份代码在无 hash 导航时手动触发，`scrollY` 从 5 一路涨到 18806，完全正常。成因是导航自身的「滚动到片段／回顶」与程序化滚动撞在同一帧，后者被吞掉。

**后果**：搜「乡校」直达 E195，卡片**确实展开了、`spotlight` 也确实闪了**，但它停在 `y=1034`——视口只有 900，**读者看到的仍是页顶，什么都没发生**。

**影响面**：`consumeTimelineSpot` 自 **r11** 起即此写法，潜伏十四轮。

**为什么这么久没人发现**，值得写下来：**过去的断言只查 `details.open === true` 与 `.spotlight` 类名——全是 DOM 状态，一条都不查像素。** DOM 状态对是必要条件，从来不是充分条件。已把这条写成 `design_notes` §7.3「DOM 状态对 ≠ 读者看得见」，与 §7.1（节点该在哪）互为两半。

**修法**：让出一帧再滚（双 rAF），抽出 `spotScrollInto` 供两处 consume 共用。

**反证已跑（§7.2 纵向自证）**：退回单 rAF 写法后，`tools/qa/vision_r24a.js` §12 三项**全红**——

| 用例 | 旧码（单 rAF） | 新码（双 rAF） |
|---|---|---|
| 编年 · 事件 E205 | scrollY 峰值 **0**，目标 y=**13474**（视口外） | 峰值 13290，y=240 ✓ |
| 编年 · 原文 Q277 | scrollY 峰值 **0** | 峰值 13423，y=107 ✓ |
| 时间线 · 事件 E195（既有路径） | scrollY 峰值 **0**，目标 y=**1034**（视口外） | 峰值 833，y=201 ✓ |

§12 因此**永久保留**，判据只有一条：**scrollY 实测 >0 且目标落在视口内**。

## 十一、上报与建议（不自行裁量）

1. **搜索落点语义改制候裁**（见 §3.5 末）：190 条事件的搜索落点统一改为编年。按任务书字面执行，若领队认为有主角挂链者仍应落其时间线，可回退 `goSearchEvent` 一个函数。
2. **`conventions` 是否需要同步**：本轮使 conventions §11 曾设想的编纂规则（「每条事件须至少挂一名主角」）不再必要——事件不挂主角也已可达，无需为可达性反向约束编纂。是否把这层关系写入 conventions，属 Skipper/领队职权，Vision 不代改，此处留痕。
3. **`places.state` 的复合写法**（8 种，如「齐鲁间」「周畿内」「申/楚」）：编年按「照显原文、取首个可识别国着色」处理，未改数据。若日后要让边地各国着两色或另设「边地」色，须先有制度判据（§2.1 判据只管九色两两与两条对比底线），非单个视图可决。
4. **「其他」类国色签 23 条**（周/曹/邢/蔡/许/纪/莒/谭/遂/庸/息/吴/郕）目前全作中性。若某国日后升为国色家族（如周），编年签会自动着色、无需改代码——但那要跑 §2.1 全矩阵复验。
5. **年段滑块**：一期未做（任务书明示），记入候选池。若日后要做，须一并决定它是否入 hash（现行筛选一律不入）。
