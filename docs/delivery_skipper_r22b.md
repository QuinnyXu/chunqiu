## 二、软检实现方式与分档开关位置

`tools/validate.py` 新增结构式软检（不使用关键词式）：

```python
CAVEAT_RE = re.compile(r"^【[^】]+】")
SOFT_CHECK_TIERS = {
    "诗歌": True,       # v1.20 首批启用
    "经义异闻": True,   # v1.20 首批启用
    "言论": False,      # 暂缓
    "后出叙事": False,  # 暂缓
    "评论": False,      # 暂缓
    # "原文" 不列表内：结构判据已直接豁免
}
```

判据：`quote_type != "原文"` 且该 `quote_type` 在 `SOFT_CHECK_TIERS` 中为 `True` 且 `modern_note` 不以【…】开头 → 计入 `warnings`（与 `errors` 分离的独立列表），`report()` 单独打印"软检警告（不阻断）"一节，`main()` 的 `return 1 if errors else 0` 不受 `warnings` 影响——**警告不阻断**，验证 `exit code` 仍为 0。

分档开关就是 `SOFT_CHECK_TIERS` 这张表本身（`tools/validate.py` 顶部，`REL_TYPES` 定义之后），逐档一行、注释写明启用/暂缓理由，日后开新档只需把对应值改 `True`，无需改判据逻辑。

**为何改结构式、放弃关键词式**：领队原议扫描"互斥／不作史实／不可与经传并置"类措辞，Sophia 实测该口径全库仅命中 6 条；结构式（无【】前缀）测得真实缺口是 **71 条**——r21 之前的条目层说明写在正文括注里（如 Q133「（经义／异闻层·史实可靠度低于左传经传）」），处置说明完整却一个关键词都不命中。关键词式的问题不是漏检，是它会绿着灯让人以为查过了。结构式的另一好处是天然豁免"原文"层——不会因为 Q192（quote_type=原文）正文末句提到"话术"二字而被误抓（判据本身按 `quote_type` 分流，Q192 从不进入检查分支，不需要额外白名单）。

1. **层标/徽标分工体例，不复述**：徽标（`.q-layer`，右上小胶囊）答"类型"——引文属 `quote_type` 哪一层，由字段本身呈现；层标（`modern_note` 首段【…】）答"性质/用法"——本库对这层材料的处置结论（怎么用、能不能当史实、与经传是何关系）。写层标不得写成"【经义异闻】"这类纯复述层名的空标签，那是该说的话没说、该省的话反而说了。
