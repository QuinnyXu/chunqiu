## 二、断言实现要点与所在位置

**位置**：`tools/qa/vision_r24a.js` §21（文件末尾、汇总行之前），标题行

```
21) r34 · 关于页版本一致性：「当前版本」行 ⇔ changelog 列表首项
```

**取节点方式（DOM 对读，不动前端）**：

1. 导航至 `#/about`，等页面渲染，一律读**渲染后的 DOM**（不与源码字面量对读，同 §7.2/§7.3 一贯口径）。
2. 版本行按 **id 取节点**：`#about-version`，取其文本中 `当前版本\s*(v\d+\.\d+)`。
3. changelog `<ul>` **没有 id**，而前端不许改，故按**形态**认它：在 `#about-version` 的 `closest("section")` 之内遍历 `ul`，取「第一个 `<li>` 以 `vN.N` 起首」的那个；其 `firstElementChild` 即列表首项，取其文本开头的 `^(v\d+\.\d+)`。——这是 §7.1「DOM 关系锚定在身份与状态上」在**无 id 可依**时的退让写法：不锚在「第几个 ul」这种位置上，而锚在「其首项长得像版本条目」这个**身份特征**上；结构一变即报「定位失败」，不会静默失准。

**两项断言（为何是两项，不是一项）**：

- **① 定位项**：关于页已渲染（`#view-about` 非 `hidden`）且两处版本号**都真读到了**。
  没有这一项，日后若 id 改名或列表挪出该 `<section>`，两边同为 `null`、`null === null` 为真——比对项会一路常绿，断言就成了摆设（这正是 §7.4「快照式断言通病」的另一形态）。
- **② 正题**：两处写死的号必须相等。

**失败信息直接可用**（任务书要求，不只说「不一致」）：两条断言共用一段 `verWhere`，把**两处各自读到的号 ＋ 各自的定位 ＋ 各自的行文开头 34 字**一并打出，比对项失败时再追加**处置指引**。注入反证时的实际报错原文：

```
[FAIL] 站内版本号自相矛盾——版本行〔#about-version〕读到 v0.18：「当前版本 v0.18（出土文献层：清华简《系年》第五章入库，与《左传…」
｜ 列表首项〔#about-version 所在 <section> 内 changelog <ul>（其下 18 个 <li>，末条为「更早」非版本条）的第 1 个 <li>〕读到 v0.19：
「v0.19 —— 出土文献层：本库第一次收入地下所出的写本——清华大…」
｜ 处置：以本轮 changelog 首项实写的内容为准回改版本行（病类见 design_notes §7.5；病例为 v0.18 那轮只加条目漏改版本行）
```

**一处记实**：该 `<ul>` 之下实为 **18 个 `<li>`**——17 条版本条 ＋ 末条「更早 —— 数据管线与三屏原型」。r33 生产复验表所记「17 条」数的是版本条，两者口径不同、皆无误；报错文案已写明「末条为『更早』非版本条」，免得后人照数字对不上而以为列表被改过。

## 三、注释里病类／病例的写法

节前注释分三段，标题即写明用途（这是本件的实质，不是装饰）：

- **【为何有这一条 · 防的病类】**——同一个版本号在 `index.html` 里**写死了两份**，两份各自独立、谁也不引用谁，只靠发版的人记得同时改；点名这是 `design_notes` **§7.5**「文案不该随数据长 —— 『写死的数字』在界面文字里的同族一相」所收之病，病根一句话：**把一份会变的事实抄成第二份，而没有人负责对账**。并说清本条与 §7.5 原举例的分工：§7.5 举的是「随数据长的**列举**」（首页无主角之国的国名清单），本条是同族的另一相——两处互抄的**同一个数**。
- **【病例】**——v0.18 那一轮只在 changelog 顶上添了一条 `<li>`、漏改上方「当前版本」行，关于页自此自相矛盾（版本行 v0.17 / 列表首项 v0.18），一直潜伏到 **r32** 走查才被撞见；**r33 修的是结果**（版本行改到 v0.19），成因原封未动。随后记明 **r34 站长裁定取方案 ①**：界面保持静态、一行不改（不改为运行时从列表首项拼装，那与本站静态优先的取向有摩擦），改由总门每次复跑时 DOM 对读兜住。并按 §7.2「**留档口径**」写明本节是**构造式断言**、落地时并无活 bug 可捉，其咬合力由注入反证证明——否则后人见其无对应 bug，会当冗余删掉。
- **【失败时往哪看】**——两处的确切位置（`<p id="about-version">` / 该 `<section>` 内 changelog `<ul>` 的第 1 个 `<li>`，并说明该 `<ul>` 无 id 故按形态认）；号不等时**改哪一处**的通例（先读列表首项那条实写了什么，再回改版本行的号与括注）；以及**两类失败的分野**——若报的是「定位失败」而非「号不一致」，那是关于页 DOM 结构变了，此时该改的是本节的取节点方式，**不是数据**。

## 五、反证注入的实测结果（§7.2「按类反证立断言」）

**为何须反证**：本条落地时**无活 bug**——r33 已把版本行改到 v0.19，两处本就一致，断言天生常绿，与摆设无法区分。

**注入什么**：**同型错误，不是自造故障**——照 v0.18 那轮的原样复刻一次「changelog 已是新号、版本行还停在旧号」：临时把 `site/index.html` 的 `<p id="about-version">` 中 `当前版本 v0.19` 改一字为 `当前版本 v0.18`（括注一字未动，正与当年漏改的形态一致），列表首项仍是 `v0.19`。

**实测（用同一份 harness 全跑，非只跑该节）**：

| 状态 | 总门实测 | §21 ① 定位项 | §21 ② 比对项 |
|---|---|---|---|
| 注入前（现状） | **511 / 0** | OK（两处均读到 v0.19） | OK（同为 v0.19） |
| **注入后** | **510 项通过 / 1 项未过** | **OK**（两处均读到号：v0.18 与 v0.19） | **FAIL** —— 报文见 §二 |
| 复原后复跑 | **511 / 0** | OK | OK（同为 v0.19） |

**三点值得记明**：

1. FAIL **精确落在**比对项，条数恰为 1，其余 510 项无一被牵动——说明这条断言看的正是它该看的东西，没有旁溢。
2. 注入态下**定位项仍绿**，故这次红是「两号不一致」，**不是**「选择器读不到」——两类失败在报文里可分，这正是设一项定位断言的用处。
3. **复原经 `git checkout -- site/index.html`**，`git status` 复核 `site/` 无改动、`grep -c "当前版本 v0.19"` ＝ 1；复原后重跑总门回到 511 / 0（**「只报新码全过不算自证」，故三态俱跑**）。
