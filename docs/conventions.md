## 1. 目录结构与数据流

```
data/csv/          唯一数据源（source of truth），所有编辑发生在这里
data/incoming/     待合入的增量数据；复核通过后手工合入 data/csv/ 并删除
tools/             管线脚本（仅 Python 标准库）
site/              静态站根目录，可整体部署到 GitHub Pages
site/data/         生成的 JSON —— 生成物，禁止手改
site/assets/       图标（icons/）与地图底图（map/）
docs/              本文件与设计文档（design/）
docs/changes/      各轮 CHANGES.md 原样归档（见 §10.1），命名 rXX_<批名>.md
private/           私有层（写作提示等，git 忽略，不入公开仓库）
```

数据流（单向）：

```
data/csv/*.csv  →  tools/csv_to_json.py  →  site/data/*.json + meta.json
```

- **JSON 禁止手改**：`site/data/` 下任何文件的改动只能来自重跑 `python tools/csv_to_json.py`。
- 每次改动 `data/csv/` 后的标准流程：`python tools/validate.py` 通过 → `python tools/csv_to_json.py` 重新生成 → 一起提交。

- **新规则**：此后凡在同一轮次内并行下达两批及以上备料任务书，**下达任务书时须在任务书正文中为各批次预先分配互不重叠的 ID 网段**（如"fix19 用 E134–E137，round20 用 E138–E170"），各批次按预分配网段起编，合入时基本无需重排；确因排期仓促未能预分配的（如本次事后才发现撞号），由合入者（Skipper）按「先确定合入顺序的批次保留原号，后合入批次整体顺延重编」处理，重编映射表须完整写入交付说明（events/sources/passages 各表旧号→新号逐一列出，foreign key 全联动），不得默认哪批"应该"保留原号而省略核对。
- **`relations`／`sources` 不预写具体号，只写"接台账尾号"（v1.25 新增，r27 裁定10）**：round27 任务书曾为 1a 件预分配「relations R264 起」，但下达时点与 1a 备料执行时点之间，主表 `relations` 实际尾号已因 r25b 合入推进至 R264（`P_SHUXIANG`—`P_YANGSHIWO`「父」），一写即撞——1a 只得改从 R265 起编，1b 再顺延至 R275 起（详见 `docs/changes/r27a_helu.md` §0.1）。经核，`relations`／`sources` 与 `events`／`passages` 有一处结构性差异：后二者常需在**同一批次内部**保持连续区间供跨条目挂靠或叙事排布（如同一事件系列的 `sort_key`/`passages` 常按顺序编号），故预分配具体区间确有必要；`relations`／`sources` 各条之间不要求连号相邻，逐条**接续当时台账尾号**编号即可满足唯一性与可读性，预写具体起始号反而在"任务书下达"与"备料执行"之间存在时间差时更容易撞号（本次即是一例）。**新规则**：此后任务书为并行备料分配网段时，`relations`／`sources` 一律只写"**接台账尾号**"（不写具体数字），由各批次备料时各自查验当时主表实际尾号后接续起编；`events`／`passages` 因跨件切分关系明确、内部常需连续区间，继续沿用上一条"预分配具体区间"的规则，但**下达任务书前须核实际尾号**（避免如本例的 R264 一类"预分配时的认知尾号"与"备料执行时的实际尾号"不同步）。

**ID 退役**：作废 ID 永不复用，也不得赋予新含义；引用它的历史提交以 git 历史为准。现有退役名单：**E005、E006**（已拆分为 E035/E036 与 E037–E039）；**Z098**（v1.27，r28 随批清账——与 `Z078` 同引《春秋左传·昭公二十八年》一篇，两源并合，保留 `Z078`、`notes` 合并 `Z098` 原文，`Z098` 退役；原引用 `events.E221.source_ids` 与 `passages.Q321`–`Q324.source_id` 已迁引至 `Z078`）。

**`T###` 前缀分层纪律（v1.10，裁定4）**：`T` 前缀专用于**先秦诸子及秦汉说部层**史料——即诸子（《韩非子》《说苑》《吕氏春秋》等）中的寓言、说理性举例，与秦汉说部/杂史中的轶闻叙事，**不是**《左传》《国语》一类当代编年记事，也不同于《史记》一类"后出叙事"的正史体例，故单立前缀不与 Z/S 混编。启用 `T` 前缀的条目须遵守：
- **严格分层**：`passages.quote_type` 一律标"经义异闻"或后续如为该层专设新枚举值，不得标"原文"；`events.reliability` **从严默认标 `low`**（诸子寓言/说部叙事常以理服人或渲染效果为先，纪年、人物细节多不可考，除非有独立经传/考古佐证方可上调），不得因文笔生动或情节完整而误标 high/medium。
- **不得单独立事件骨架**：`T` 类史料只作为已有经传骨架事件（`Z`/`S` 等来源支撑的 `events` 行）的旁证摘录挂入 `passages`，不得仅凭诸子/说部材料**新建**一条 `events` 行——避免寓言、说理故事被误当作编年史实收入主线。
- **不立 `people` 行、不织 `relations` 边**（v1.23 新增，r25 裁定e）：`T` 类史料中出现的、经传无征的人物（如仅见于诸子/说部的配角），或据此类材料方能成立的人物关系，一律不新立 `people` 行、不新织 `relations` 边，只在其挂靠的 `passage`（`quote_original`/`modern_note`）与所涉 `sources.notes` 中保全其名与关系。理由与"不得单独立事件骨架"是**同一道防线的两侧**：`people`/`relations` 两表均无分层字段，一旦入表即与经传所出者同列、读者无从分辨层级，等于让说部材料从后门进入事实层。先例：round25a 第二件《晏子春秋》示范批——使楚二章之楚王（后世指为楚灵王系附会）、二桃杀三士之三士（公孙接、田开疆、古冶子），均未立人物行、未织关系边，经领队核可成通例（详见 `docs/changes/r25a_yanying.md` §B5、§B7 第 2 点）。
- **来源标注**：`sources.notes` 须注明其"诸子说理"或"说部轶闻"性质及成书年代层级（先秦诸子 / 秦汉杂史），供合入者与读者一望而知非当代记事。

**`S###` 前缀广义化为「秦汉正史层」（v1.25 新增，r27 裁定12）**：`S` 前缀原仅指《史记》，v1.25 起广义化为**秦汉正史层**，涵《史记》《汉书》等纪传体正史；仍与 `Z`（左传）、`G`（国语）等当代编年/记言文献分列，不与之混编，`events.reliability` 之标注纪律不变（后出叙事层，须标层，不得径升经传骨架）。**起因**：`docs/kaoding_wudu.md`（吴都地望考订）§五指出《汉书·地理志》"吳，故國，周太伯所邑"一句是甲说（苏州说）文献链中年代最早、分量最重的一条正史地理志明文，而九前缀（`Z/S/G/A/P/B/Y/L/T`）中《汉书》无所归属；round27a 因此暂取最小处置，只在 `L_WUDU.description` 中以文字引述而不建 `sources` 行（详见 `docs/changes/r27a_helu.md` §2.3）。领队采纳 Sophia 在考订文档 §五所倾向的方案①（"扩 `S` 的语义为『正史』，改动 conventions §2 表述，影响面小"），改动仅及本文件释义与既有 `sources.notes` 撰写口径，**不改 `tools/validate.py` 正则**（`^[ZSGAPBYLT]\d{3}$` 本已含 `S`，字母集不变）。**《汉书》来源行已补建（v1.27，r28 随批清账）**：`S014`《汉书·地理志下》（会稽郡「吳，故國，周太伯所邑」一句，`L_WUDU` 甲·苏州说文献链中年代最早、分量最重之一条来源），`work` 栏作「汉书」，`notes` 注明其性质为「东汉正史地理志」以别于《史记》一类「西汉正史」；`L_WUDU.source_ids` 已挂入本行，原 `description` 中的文字引述保留不动（正式来源行与行文引述并存，互不排斥）。

**`J###` 前缀分层纪律（v1.30 新增，r32 裁定，据 `team/ruling_chutuwenxian.md` 十一条领队裁定书）**：`J` 前缀专用于**出土文献层**史料——战国竹书为首（清华简、上博简、安大简等出土简牍同层），首条为 `J001`（清华简《系年》第五章）。启用 `J` 前缀的条目须遵守：

- **独立见证层，与 `Z`（左传）平行、不设高下**：`J` 层不是 `Z` 层的补充或旁证，而是与之并立的另一支独立记载；两支记载互证处相互加强，相抵处并陈不裁（见下方 §7「出土文献与经传异文，并陈不裁」通例），不得因 `Z` 层历史更久或篇幅更大而径自压过 `J` 层。
- **`J` 单独支撑者默认 `medium`**：某史实仅见 `J` 层、无 `Z`／`G`／`S` 等传世文献互证时，`events.reliability` 默认取 `medium`，不径升 `high`。理据有二，须入规范原文义：**「出土文献之早是载体之早、非记载之早」**（简牍抄写年代早于传世本流传定型的年代，不等于其所记之事的原始记录时点也更早，二者是两回事，不得混为一谈）；以及**入藏简来源链的额外不确定性**（凡非科学发掘、经由购藏/捐赠入藏的简牍，其出土地点、流传经过缺乏考古学意义上的现场证据链，真伪与完整性只能依赖学界事后鉴定，此项不确定性传世文献所无）。
- **四条尺度**（判定某条 `J` 层材料之 `reliability` 与是否可单立事目）：① 与传世文献**互证**者，可从 `medium` 上调 `high`；② `J` 层**独有**而其事**属编年骨架**核心（如系年本身、灭国存灭等大事）者，取 `medium`；③ `J` 层**独有且与传世文献相抵**、或释读上**属系争议关键字**者，取 `low`；④ **国势总结语**（如篇末收束一段因果之总账、不与逐节记事分栏者）**不作史实骨架用**，只作 `passage` 挂靠、不单独立事目（**与 §7「总括语与详叙不径判相抵」分工**：本条管**篇末断语**，彼条管**行文中之总括叙述**，v1.33 补，r40 裁定 4）。
- **入藏简性质固定著录**：凡非科学发掘之入藏简，`sources.notes` 必著一句其入藏／发现性质（如"由校友捐赠入藏，非科学发掘出土品"），使 `medium` 默认的理据在该行注文中可见，不得省略——理据必须可见，不能只留一个默认等级而无人知道为何默认于此。
- **`sources.category` 新值「出土文献」**（v1.30，r32 裁定 11）：随 `J` 前缀落地新增，供 `J` 层条目著录（`validate.py` 对 `category` 无枚举校验，本值不触发阻断，纯撰写口径约定）。
- **同层内批次区分办法（不加栏）**：`J` 层不新增数据列区分批次/丛书，沿用现有八栏：`work` 栏填批次丛书名（如"清华大学藏战国竹简"），`section` 栏填篇名·章次（如"系年·第五章"），`title` 栏填含册次的全称。
- **金文归 J（预防性裁定）**：青铜器铭文属出土文献层的文本证言，与器物本身（考古实物）性质不同——**一物两录**：器物入 `A###`（考古），铭文文本入 `J###`（出土文献），两行并立、`notes` 互指，不得合并为一行。本库现无金文条目，先立规矩、后遇事时依此办理。

## 3. 事件分类枚举（events.category）

共 **17** 个，图标一一对应（`site/assets/icons/` 下按同名维护）：

```
即位, 战争, 会盟, 相会, 婚嫁, 生育, 出奔, 弑杀, 薨卒, 丧葬, 外交, 内乱, 灾异, 礼俗, 政制, 论对, 其他
```

「相会」与「会盟」的区分：「会盟」指诸侯/国家层面的正式会、盟、朝聘；「相会」指个人之间的私会或非诸侯会盟性质的相见（主要用于文姜与齐襄公一线）。

「政制」（v1.21 新增）：制度建置/治绩类事件，即"如何治国"本身构成事目核心，而非某一具体的即位/战争/会盟等行动——如 `E187`（管仲为政：叁国伍鄙、作内政而寄军令）、`E131`（孙叔敖为相与治绩，原归「礼俗」，随本次新类改归）。与「礼俗」的区分：「礼俗」取礼制/习俗层面的事目（如丧礼、婚制细节争议），「政制」取治国之制（军政、户籍、职官一类国家机器本身的构造）。**图标补齐为 r24 Vision 配套待办**（仅在此登记，未实现）——补齐前，`政制` 类事件在依赖分类图标呈现的前端位置可能暂缺专属图标，不影响数据本身的正确性。

「论对」（v1.23 新增，r25 裁定i）：以谏诤、问对、贺辞等**记言**为事目本体、无独立行动骨架（非战/盟/弑/奔等具体行动）的政论性事目——即"以言为事者"，如谏对、论贺、书辞一类。源出 v1.22 枚举注记备考所登记的「政论记言」观察项（`E188`、`E212` 两条）随 round25b `E220`（叔向贺贫）落地满三条、触及登记门槛，领队核可新增此类。**首批迁入 3 条**：`E188`（子产谏侵蔡之喜）、`E212`（晏婴「和与同异」之对）、`E220`（叔向贺贫），三条原均归「其他」。`E196`（郑铸刑书相关记言，若属此类边界个案）**观察项已于 v1.24 关闭，维持归「政制」**：`E196` 有独立行动骨架——传文以「三月，鄭人鑄刑書」发端，铸刑书是有月份、有实施主体、有物质产物（刑条铸于金器）的制度建置行为，而「论对」定义要求"无独立行动骨架"，两者不合；且该事目自身 `summary` 首句即自称"亦为本库「政制」类之典型事目"、`title` 以「郑铸刑书」居首，叔向诒书与子产复书虽精彩，是围绕该建置而起的往复、非事目本体。详见 `data/incoming/fix26/CHANGES.md` §2.5。与「政制」的区分：「政制」的事目本体是制度之实（治绩、建置本身），「论对」的事目本体是言辞应对本身，不涉制度建置或不构成独立行动。**图标补齐登记为 r26 Vision 配套待办**（与「政制」图标缺口合批处理，本轮未实现），补齐前 `论对` 类事件在依赖分类图标呈现的前端位置可能暂缺专属图标，不影响数据本身的正确性。

- 每个事件只取一个分类；复合事件取对主线叙事最核心的一面，拿不准时在交付说明中列出待复核。
- `importance`：`1`=主线关键，`2`=重要，`3`=背景。

**枚举注记备考（v1.22）**：`E205`（齐太史书「崔杼弑其君」，兄弟继死其职、南史氏执简以往）分类取「其他」——核心在直书与守职，非杀戮本身，归「弑杀」会误导前端呈现其分量；现行类无「史职/书法」一目，新增一类须走 §3 枚举扩充程序，非单条事目可决。**史笔类暂归其他，积三再议**：待此类"史官直书、守职殉道"性质的事目积够三条（现仅 E205 一条）时，再评估是否值得单立一类，本次不因一条孤例扩枚举。**「政论记言」观察项已于 v1.23 转正为「论对」类，见上**，本条备考不再适用于该类事目，仅保留史笔类的积三再议记录。

## 5. reliability / certainty 三级标注

适用于 `events.reliability`、`places.certainty`、`places.coord_certainty`、`background.certainty`、`archaeology.certainty`：

- `high`：可作为骨架直接使用。
- `medium`：宜复核后使用。
- `low`：只适合作线索，不可直接当事实。

补充提醒（同旧库）：《诗经》条目是传统阐释和舆论层材料，不直接等同于编年史实；考古表目前是写作型摘要，学术级使用需补发掘报告出处。

**`certainty` 与 `coord_certainty` 分工语义（v1.24 新增）**：`places.certainty` 与 `places.coord_certainty` 表面同为三级标注，实则答的是两个不同问题，不得混用同一套判断依据：

- **`certainty`** 答的是**「这个古地名与今地的对应是否可靠」**——即身份问题，"这地方是不是它"。
- **`coord_certainty`** 答的是**「所取坐标落点是否戳准」**——即精度问题，"点有没有戳准"。

多数条目两值同向（地望越可靠、坐标也越可靠），但并非必然——**遗址类地点天然容易出现"位置极准、身份存疑"的反向组合**：考古实测坐标精确无异议（`coord_certainty=high`），但该遗址是否即史料所指某地仍有学界异说（`certainty` 只能取 `medium` 甚或 `low`）。反之，一个地望本身通说无异议、但取点落在群体遗址一带（如都城遗址群跨数平方公里）而非单一具体建筑基址上的点，则可能是 `certainty=high` 而 `coord_certainty` 因取点精度问题略降。两值背向而行时须在 `coord_basis` 中写明缘由，不得视为数据矛盾而强行拉齐。源出 `docs/kaoding_wudu.md`（吴都地望考订，C 段前置文档）§3.2 提案原文义，随 fix26 领队核可成文；`L_XINTIAN`（新田，晋后期都城）为本库首个明确套用本分工说明的条目——其 `certainty`／`coord_certainty` 均取 `high`（地望本身无异说，考古遗址群与经传地理判据互证；坐标取古城群一带质心近似，在本库投影尺度下不构成实质精度差异，`coord_basis` 已自限说明）。

## 6. CSV 编辑规约

- 编码 UTF-8，逗号分隔，首行表头；单元格内多值用 `;` 分隔（如 `source_ids`）。
- `year_bce` 为**负整数**表示公元前（前694 → `-694`），有效范围 **[-800, -464]**（v1.24 放宽，原 [-800,-480] 已不敷 C 段吴越篇——《左传》记事下限前468、越灭吴前473、勾践卒前465（《史记》系年）均越界；新上限 **前464** 取《左传》全帙下限——哀公二十七年传末"悼之四年"一段（晋荀瑶帅师围郑，鲁悼公四年＝前464），与本库"左传为经"的定位一致，比仅覆盖勾践卒的 -465 多留一年、不额外引入战国事目风险。**本约束同时施加于 `events.year_bce` 与 `people` 的 `birth_year_bce`/`death_year_bce` 两处**——`tools/validate.py` 中二者共用同一 `YEAR_MIN`/`YEAR_MAX` 常量（第31行定义，第186/248行两处分别校验 events 与 people），改动该常量即两处同步生效。历史：v1.11 放宽，原 [-800,-600] 已不敷春秋中晚期史事——楚庄王卒于前591、邲之战前597 皆晚于旧上限；上限前480 覆盖传统春秋下限前481/前476 一带，为该期主角入库的前置 schema 调整，领队裁定，该轮仅边界放宽、无数据变更）。
- 旧数据行的新增列允许留空；空值一律用空字符串，不写 `NULL`/`N/A`。
- 新增数据先进 `data/incoming/`，复核后合入 `data/csv/`。
- `event_people.presence`：枚举 `{亲至, 相关, 不在}`，允许暂空（**空视同亲至**）。亲至=此人当时身在事发地（史文明书）；**相关=史文无其在场明文（非断言不在场）**（v1.18 订正，原表述"事件与其相关但本人不在场"是断言其不在场，与判据分寸相反——「相关」标的是"史文未明书其在场"这一文本事实，不是"此人确实不在场"这一历史论断；常见于为其议婚、他人代行、谏语问对无独立地点明文等场景，均属"未书"而非"已断其不在"）；**不在**（v1.27 新增，r28 裁定 c）=**史文正面明书其人不在事发地**——与「相关」同为"此人不构成亲至"，但证据强度不同：「相关」是史文对其在场与否**未置一词**（消极证据），「不在」是史文**明文写出**其人身在别处（积极证据，如"令大夫種守於國"）。首用例：`E266`／`P_WENZHONG`（大夫种守国）。`tools/validate.py` 的 `PRESENCE` 集合已同步扩一值；**前端展示暂同「相关」处理**（未另设专属视觉样式）；**不回溯扫库**——本值只用于此后新增/修订时史文确有"正面写明不在场"之明文者，不要求普查既有"相关"行是否应升级为"不在"。判据源出 round28b `E266`（文种）与 `E250`（范蠡）两例（后者本轮未采用，留观察），领队核可后正式启用。
- `events.sort_key`：可空整数；同一 `year_bce` 内按 sort_key 升序排列，按经传季月定值，建议以 10、20、30 间隔留插空。同一年内非空 sort_key 不得重复。

## 6.5 relations 表（v1.5）

表头 `id,person_a,person_b,rel_type,rel_label,reliability,source_note`。rel_type 枚举 8 类：`亲属-直系, 亲属-同辈, 婚姻, 君臣, 拥立, 敌对, 师友, 其他`。方向约定：**person_a 是 rel_label 的主语**（a=郑庄公、b=郑昭公、label=父）。每条关系只录一行、不录反向重复；同一对人物允许多行但 rel_type 必须不同。异说关系降 reliability 并在 source_note 说明。`people.relations` 自由文本列保留（人读友好），结构表供图谱等程序使用。

## 6.6 people.state 分组标注规则（v1.15 定，v1.18 订正为「全链」）

`people.state` 此前的非成文惯例是标注人物的「首国」（即原生/最初所属国），v1.15 起正式修订为**「人物线主要发生国」**标注。**v1.18 订正标注口径为「取全链」**：`state` 须把其人物线实际经停的**全部**主要国家依时间顺序列出（`/` 分隔，出身在前、归宿在后，**中途经停国一律不省略**），不再只取最初一国，也不得只取「出身、归宿」两端点。

- **订正起因**：v1.15 原表述「出身→归宿标注」在实践中易被读作只取首尾两国——夏姬（`P_XIAJI`，r21 新主角）人物线实为**郑→陈→楚→晋**四段，若按"首末"误读只填「郑/晋」，恰好吞掉陈、楚两段，而那正是她人物线的叙事主体。Vision r21 前端走查发现此问题，领队采纳订正为"全链"（Vision r21 前端已按全链呈现夏姬「郑→陈→楚→晋」，连带息妫「陈→息→楚」一并核对）。`data/csv/people.csv` 中 `P_XIAJI.state` 现值已是 `郑/陈/楚/晋`（全链），本条订正是把已落地的正确口径回写入书面规范，不涉及数据改动。
- 范例：庄姜、宣姜均齐女嫁卫，`state=齐/卫`（仅两国，全链与首末结果一致，不受本次订正影响）；息妫陈女历嫁息侯又归楚，`state=陈/息/楚`（三国全链）；秦穆姬晋女嫁秦，`state=晋/秦`；**夏姬郑→陈→楚→晋四段，`state=郑/陈/楚/晋`**（本次订正的直接案例，四国全链、无省略）。
- 校核范围：本规则为溯及既往的标注纪律，不要求立即普查改写库内全部既有人物行；新增/改动人物时按"全链"口径填写，既有人物如在后续增量中被提及或需要更新，顺手按新口径校核并可以修订。
- 与「首国」旧惯例的关系：旧惯例未曾成文入本文件，此前各批次已有按"主要国+全链"实际填写的先例（如既有 `P_MUJI` 穆姬 `state=晋/秦`），本条只是把已在实践中稳定下来的做法正式写入规范，不构成对既有数据的推翻。
- **判例（v1.19）·全链仅限各站有其人明文，不得以其主君/所属者的行程代填**：round22 备料曾提请是否应把介之推（`P_JIEZHITUI`）`state` 按晋文公流亡所经诸国（狄/卫/齐/曹/宋/郑/楚/秦）整条填全链——领队裁定**不采纳**，维持单一「晋」。理由：《左传·僖公二十四年》仅一句"晋侯赏从亡者，介之推不言禄"证明其曾从亡，从亡起讫、所经何国经传只字未书；《史记·晋世家》"从亡五士"（赵衰、狐偃、贾佗、先轸、魏武子）亦不列其名，其人首次见于《晋世家》即在渡河一节（前636），此前诸国均无其名。用主君的行程代填从者的行程，与 §6「presence 从严」禁止的"以身份推定在场"是同一类错误，只是换了字段——「全链」标注的前提仍是**其本人**在该国有行止明文，不是所属团体/主君去过就代记。
- **判例（v1.19）·流向只记政治身份迁转，往返避难型出奔复归不入**：round22 备料曾提请鲍叔牙（`P_BAOSHUYA`）`state` 是否应按「奔莒又反齐」写作全链 `齐/莒/齐`——领队裁定**不采纳**，维持单一「齐」。理由：本条规则的设计初衷（夏姬郑→陈→楚→晋、息妫陈→息→楚）针对的是**政治身份/婚姻归属的迁转**——每一段代表其人身份归属地的实质变更（改嫁、易国事君），中途国不可省略正因为那是叙事主体所在。鲍叔奉公子小白奔莒是**为避国乱而临时出亡**，事定即随小白反齐复位，齐国国内身份自始未变，莒只是出亡避难的中途点、不构成身份归属的迁转段。故「取全链」只适用于身份迁转型人物线，往返避难型出奔复归（奔而复归、本国身份不变）不计入 `state` 流向；`notes`/`role_in_event` 文字仍应如实记录奔莒一节，不因此从数据中删去该段史实，只是不进入 `state` 字段的国别流向标注。

## 7. 私有层与叙事分层（v1.3）

- **私有层**：一切写作向列（历史上以 novel 开头命名的两个备注列，及后续任何写作向字段）不入公开数据，统一存 `private/writing_notes.csv`（通用三列 `table,row_id,note`；`private/` 整目录 git 忽略）。校验器对公开表头设有护栏：任何以 novel 开头的列名直接报错。增量包如有写作向备注，写在 CHANGES 附注区由合入者转存私有文件。
- **presence 从严通例**：凡"师行而君亲在无文"（某师伐某、某人灭某）、"使者代行"（使贼、使宛）、"称疾不往/不从"及追叙关联者，一律标「相关」；只有史文明书其人在事发地（会、盟、战、朝、奔、生卒于其地）方标「亲至」。宁严不滥。
- **后出叙事分层通例**：《史记》及更晚文献中戏剧化情节（射钩佯死、曹沫劫盟、彭生化豕之类），须在 summary 或摘录 quote_type 标明"后出叙事"层，不得与经传记事混写；科普展示面引用时保留分层标注。

- **判例（v1.19）·有系年（可推定）且有行动落点的对话/荐举类记言材料，可单独立事件**：本条通例针对的是"系年阙如"的评价性语录/追叙轶事，不等同于"一切原文不自带年月的记言材料"一律不许立事件——round22 备料的 E186（桓公使鲍叔为宰、鲍叔辞相让贤，《国语·齐语》开篇）即为界定此边界的判例：领队核对后维持单立，理由有二，缺一不可：① **系年虽非自证，但可由紧邻的编年骨架推定**——《国语》原文本身不系年，但其"桓公自莒反于齐"一句紧接《左传》庄公九年"夏，桓公自莒先入即位"，系年可由此推定（故 reliability 标 medium 而非 high，推算依据须写明，不得含糊标 high）；② **有独立的行动落点**——事件落于临淄，且桓公、鲍叔牙二人均标"亲至"（面对面问对，在场明文俱全），不是空判无着落的语录。两条件同时成立方可立；只满足系年可推定而无独立落点、或只有落点而系年确实阙如，仍应依本条原通例挂靠既有骨架事件，不得比照单立。
- **判例（v1.20）·层标/徽标分工体例，不复述**：`passage.modern_note` 首段【…】编者层标与前端引文分层徽标（`.q-layer`，右上小胶囊、随 `quote_type` 着色，见 `docs/design/design_notes.md` §3.5/§3.6）分工不同，写层标时不得重复徽标已经承担的信息：**徽标答"类型"**——这段引文属于 `quote_type` 枚举中的哪一层（原文/言论/后出叙事/诗歌/经义异闻/评论），由字段本身呈现，无需在【】里重申层名（不写"【经义异闻】"这类纯复述层名的空标签）；**层标答"性质/用法"**——本库对这层材料的处置结论，即"怎么用、能不能当史实、与经传骨架是何关系"（如"不作史实用""与《左传》互斥""非编年记事""毛序异说"），是编者下的判断句，不是分类标签。判据来自 r22 收尾核订 Q227 一类条目——层标若只复述类型，读者读不到本库真正要传达的"处置结论"，等于该说的话没说、该省的话反而说了。

- **通例（v1.30 新增，r32 裁定，据裁定书裁定 3、10）·出土文献与经传异文，并陈不裁**：`J`（出土文献）层与 `Z`（左传）等传世文献系统若为**独立成书之两支记载**（非同一文本之版本异文、无祖本或抄本关系），其相异处一律**并陈不裁**，不得比照本库既有版本异文判例（如 `Q316`「以棄社稷」、`Q379`「大之至也」，两者均为**同一文本**传抄過程中产生的版本异文，有善本可资校勘）径行择一为正。通则灵魂一句入规范原文义：**「版本异文有善本可问，独立两支无正本可言，不得比照择一。」** 三种例外及限定语：① **独立第三方可断**——须与二说均无源流关系的第三方材料方可援引断案，注家之说、与其中一方同源的传世材料（如 `Q161`／`E146` 场景下的《史记·管蔡世家》，与《左传》同属传世系统）不构成独立第三方；② **异出于释读／转录层面者径作用字注**——须已取得整理本核定方可如此判，未取整理本前一律标"待纸本"（见下方"转录本可证有无某事"口径句），不得以电子转录本代整理本释文；③ **一方与自身内证相抵者只降权重、不改并陈格局**——如某支记载内部前后文自相矛盾，只影响该支材料的可信权重，不因此改变两支材料并陈不裁的整体格局。**并陈是双向义务**：只在一侧（如仅在 `J` 层引文中）注明异说，而传世文献一侧不作回指，等于把 `J` 层实质降格为传世文献的附注——"只在一侧注异，等于把 J 层降成附注"。故两侧注文须互指，首例即 `Q161`（《左传》一侧）↔`Q442`（`J` 层一侧）双向互指。**一对多时的落点规则（v1.33 新增，r40 裁定 6）**：并陈之双向义务在「一对多」（一条 `J` 层引文对应经传一侧数条骨架事目，如历聘行次跨六目）时，落点规则为——**`J` 引文文字所涉之事目一律增句**（增句内容按该处是同是异如实写），**`passage` 级互指只落于异之所在**。取「一律增句」而非「择要增句」，是为免主观取舍，界限机械可核。首例：`Q449`（《系年》第六章历聘行次）之 `passage` 级反向互指只落 `Q085`（卫站，异之核心），而 `E086`–`E092` 七条事目一律 `summary` 增句。**「异消解」之判定亦须双向可读（v1.36 新增，2026-09-01 站长裁定，甲案）**：用字核定后判为「从来不是一处异」（即异已消解）者，两侧注文亦须互指其判定与依据——不得因⑥「`passage` 级互指只落于异之所在」字面只落一侧，致传世文献一侧读者无从知晓此处曾经查检、如何消解。首例：`Q161`（《左传》一侧）↔`Q442`（`J` 层一侧），莘案（第五章「新／莘」，2026-08-29 站长据整理本纸本扫描本核字消解，见【★r41 裁定 18】①）。（**注·裁定理由**：Sophia 备料时报此项与⑥「只落于异之所在」正面相抵，交裁；站长裁定原文——"消解之异"与"从无之异"不是一回事：后者无事可指，前者有一段判定史（曾疑为异、经站长核字而证同）；⑥"只落于异之所在"的立法本意是防"无异滥指"，不是要抹掉"有过疑而后决"的痕迹；而"条件关闭须留痕""改正之迹照留""收敛履历照录"是本库更高阶的通则，莘案正落其下。所以这不是给正条开口子，是把"异之所在"校准为**"异或其判定史之所在"**。裁定原文见 `team/round44_prompts.md` 领队裁定备案第 4 条，2026-09-01；落地件 `docs/changes/r44_huzhi.md`。）
- **口径句（v1.30 新增，r32 裁定 9）**：**「转录本可证有无某事、次第如何，不可证某字作某。」** 出土文献之电子转录本（如维基文库据出土简牍释文转写为通行字之页面）与整理本释文在引用效力上有别——转录本可用以判断某事有无记载、事件先后次第如何，但不可据以对具体用字（通假、异体、疑难字释读）作出断言性判断；凡涉及具体用字之异文，未取得整理本纸本核定前一律标"待纸本"，不得以推理代核对（与 §10.2「有界扫描的留痕纪律」自限一条同一道防线）。**「名物用字之异」不入三层（v1.33 新增，r40 裁定 2）**：专名、地名一类**文字层**之异写（如「里之克／里克」「悼子／卓子」「梁城／解梁城」），**不入事实相抵三层**（§7「异之性质」框架三层细分判例），径归本口径句辖区处置，未取整理本核定前一律标「待纸本」并挂「悬（待纸本）」（见下方新设状态标）。**名物用字之异不构成事实相抵，不改变顶层同异之格局。** 措辞层只管**史家叙述层**之差异（同一段对话／同一行动的转述用语不同，所指行动一致，可判、可并陈）；名物用字之异管**文字层**（专名、地名之异写，判不得、须纸本）——不使可判之层容纳判不得之材料，即本条要义。首例：`Q446`／`Q447`（《系年》第六章「里之克／里克」「悼子／卓子」「梁城／解梁城」）。**【原簡】隶定栏自限（v1.33 新增，r40 裁定，Sophia 提请、站长核可）**：部分出土文献转录本于通行字正文之后另附【原簡】隶定字序一栏（如维基文库「清華大學藏戰國竹簡/系年」页），其形貌极似「原字」，极易被当作用字之证；本库从严视其为**同一转录本自附之材料，非整理本释文**，**只用以复核简号与字序，不据以判定某字作某**，口径不因之放宽——此栏是本口径句最容易被绕过的一个口子，故明文自限。首例：`J002.notes`（清华简《系年》第六章）。**名物用字之异核定后之状态词，与「同指一地」之分账（v1.34 新增，r43）**：名物用字之异经纸本核定后，其判由「待核」落为「**已核定**」，悬标解除，而顶层同异之格局仍不因之改动；又，专名／地名之**用字**既核，不等于其**所指**已定——「是否同指一地／同指一人」属地望或人物同一性之问，另立一账、依各自之考订优先序办，不挂用字之悬标。首例：`Q447`（《系年》「梁城」／《左传》「解梁城」，用字已核而地望之问仍开）。**【原簡】隶定栏自限之两用之界（v1.34 补首证，r43）**：隶定栏可用以**核对简号与字序**，不可用以**判定某字作某**——首证即《系年》第六章「牙」字：该栏亦作「牙」，与整理本正读「與」不合（**判字则错**），而以该栏核简号得「简 34 之末字」，与整理本所记简号相合（**核号则准**）——一正一反，划清两用之界。**纸本扫描本视同纸本核字，著录必带「扫描本」三字（v1.34 新增，r43 裁定 18）**：整理本／释文本之**纸本扫描本**（存字形，与重录转录本有本质之别）核字可视同纸本核字，据以解除「待纸本」之标；惟著录须如实标明其为**扫描本**，不与经手纸本原书混同。首例：`J002`（清华简《系年》第六章五处用字，站长纸本扫描本核对，2026-08-29）。**「否定性核字结果之效力自限」（v1.34 新增，r43 追加裁定 23，annot／zhiben2 两路共同拟议）**：核字之结果有正负两种：**正面结果**答「此处作某字」，**否定性结果**答「此处不作某字」，二者效力不等。**否定性核字结果只证「不作某字」，不得据以推定「作何字」**。欲定其作何字，须另有一次**正面核字**；在正面核字到手之前，该处一律维持「未核」——不得因已排除某一读法而顺势采纳次优读法，亦不得视为「二选一已去其一，故余者即是」。**排除法在用字上不成立**，因候选之集本不封闭：一个字不作「牙」，并不意味着它只能是当初被列入选项的那几个。**首例**（第六章「牙」案）：站长第一次核字所得为否定性结果——「第六章未见牙字」，本库据此记 `unknown`、未采学界通行读法「迓」；及站长复核得正面结果——实作「**與**」，句「秦公率師與惠公戰」（简 34）——该处方得定谳。**两步之间不可跳**：若当日据「不作牙」径推「当作某」，纵使猜中，其为猜亦不改——本案「與」与彼时唯一可及之通行读法「迓」并不相同，是此条自限的一次实证反证。**与既有两条之分工（三条同族而各管一段，不可互相顶替）**：

| 条 | 所管之情形 | 自限 |
|---|---|---|
| 本条（否定性核字自限） | 核了，得的是否定结果 | 只证不作某字，不推作何字 |
| 未问不推（`Q442` 之处置） | 没核，因为没问 | 站长答一字而未及相邻之字，不据前者推后者——同一字在同一段未必同读 |

**适用范围及于地望**：谭图某幅「未标某地」同为否定性结果——只证该幅不为此点作证，不构成该点地望之反证，亦不得据以推定其当在何处（同 r27c 通例「差别不在核对做没做，而在核对到了什么」）。首批案例见 r43 `L_ZHULIN`／`L_XUGE`／`L_CAONAN` 三点；另见 r31 `L_YU` 一案之教训（当日以「谭图未标盂」为负证，实系误查他幅）——否定性结果连自身之成立都比正面结果脆弱，益当自限。
- **判例（v1.30 新增，r32 裁定 5，v1.33 补，r40 裁定 1/2/3/4/5）·「异之性质」框架三层细分**：判断经传记载与其他独立史料来源（含 `J` 层出土文献）之异同时，顶层二分——**详略之别**（一方有载、一方无载，不构成相抵）／**事实相抵**（两方均有载而内容不能并立）——维持不动；本轮在「事实相抵」之下新分**三层**，保二分之简、得三层之实：**措辞层**（相抵最浅，如同一段对话的转述用语不同，但双方所指行动一致——**只管史家叙述层之差异，不涵专名／地名一类文字层之异写，后者归「名物用字之异」，不入三层，见上方口径句**）；**行动层**（两支记载对同一行动本身的描述不能并立，是相抵之核心）；**次第层**（两支记载对事件发生的次数、间隔、先后顺序记载不同——**限于编年体的系时之异；不系时之记载，其行文次序不径作先后之断言**：凡一方通篇不系月日、以事相属，其叙述顺序不足以充当先后之断言，只记不判，不计入次第层之相抵；若一方有干支／月日系时，则其次第之异为真次第层）。三层相抵之分量依次加深（措辞层最浅，行动层与次第层最深）。首例即 `J001`／`Q442` 与 `Q161`（《左传·庄公十年》）对读三节：止息妫之辞（措辞层）、蔡侯所为（行动层）、灭息之次第（次第层，落于 `E147`／`Q442` 一段）。**「事实相抵」分强度：硬相抵／并存之异（v1.33 新增，r40 裁定 3）**：两说**不可并存**者为**硬相抵**（同一位置不能同时为二，如同一人立同一君而立者两说不同、一人一次出亡之途而途中某站位次两说不同）；两说各记一端而**事可并立**者为**并存之异**（如召之与送之可以同时发生、使某人杀之与某方杀之非必不能同真）。并存之异**仍在事实相抵之内**（非详略之别——不是一方有载一方无载，而是两支各以其一端为动因、各有归属之意），本库并陈不裁、不代为调停、不判孰主孰从。强度之别只影响著录之措辞与读者之理解，**不影响 `reliability`**。首例：`Q446`（立卓子者，行动层·硬相抵）、`Q449`（历聘行次，次第层·硬相抵）、`Q450`（秦召／楚送，行动层·并存之异）、`Q451`（杀怀公之主体，行动层·并存之异）。**总括语与详叙不径判相抵（v1.33 新增，r40 裁定 4）**：记事体之**总括语**（如「讒……而殺之」一类总括致祸之由的短句）与编年体之**详叙**（详载不辩不奔、系日、自缢之状一类行动描述），**不径判事实相抵**，判**详略之别**并注明其为总括——总括语所言者是致死／致败之**由**，不承担对**行动之状**的描述效力。本条与 §2「`J###` 前缀分层纪律」尺度④（篇末国势总结语不作史实骨架用）分工：尺度④管**篇末断语**，本条管**行文中之总括叙述**。首例：`Q444`（《系年》「乃讒大子共君而殺之」对《左传》「縊于新城」，改判详略之别）。**状态标「悬（待纸本）」，正交于三层（v1.33 新增，r40 裁定 1）**：判两支记载之异同时，若**同异之成立与否本身系于一未核之字**，不得先判同异再分层——此时应标状态「**悬（待纸本）**」，**不落三层**，并写明解悬后之去向（核定作某则归同／落某层）。「悬」**正交于**措辞／行动／次第三层：三层答「异有多深」，「悬」答「异是否成立尚不能判」，不是第四种异型。原被迫塞入措辞层之「判不了」，自此与「已判为措辞之异」分开。首例：`Q443`／`Q073`（《系年》「婢妾」／《左传》「嬖」）——若「婢」读为「嬖」则两支全合、异自消；若读本字，则落措辞层。**解悬之著录三要件（v1.34 新增，r43）**：解「悬（待纸本）」标时，须逐一写明 ① 所核得之字、② 所依之**预登记去向**（立标当日已写死者）、③ **回退条件**（若日后见反证，本判当回退为何）；三者缺一，解悬即成不可回溯之断言。首例：`Q443`（《系年》第六章「婢妾」／《左传》「嬖」，2026-08-29 解悬定案，见下 v1.29 通例追补）。
- **判例（v1.21）·`source_ids` 是"本条所引全部来源"而非"骨架依据"**：`events.source_ids`（及 `places`/`background`/`archaeology` 同名字段）语义是结构性的"来源清单"，判据只要求**正向包含**——某 `passage` 引文之源，必须出现在其所挂事件的 `source_ids` 中——不要求反向穷尽，即某源出现在 `source_ids` 里也不代表该事件下必有该源的 `passage`（先例：`E046` 的 `S001`《史记·齐太公世家》自始无对应 passage，作为事件来源仍成立）。**反面提醒**：不得仅凭某来源出现在 `events.source_ids` 中，就推断其为该事件的史实骨架依据——材料的史实层级只由各 `passage` 的 `quote_type` 与 `modern_note` 首段【】层标判定。典型案例：`E176`（陈灵公事）`source_ids` 含 `P011`《陈风·株林》，是因为该事件下确有引 `P011` 的 `passage`（Q180），但 `P011` 仍是 P 层舆论材料、不作史实用，不因其出现在 `source_ids` 里而升格为骨架来源；`E176.summary` 已就此专门写明"仅表其为本条所引之源，不表其为史实骨架"。源出 r23 fix23 首批 §六第 4 点提请，本次裁定采纳并成文。
- **判例（v1.21）·注家之说不当经传明文用**：判断人物/事件同一性等事实性结论时，若某说仅见于后世注家（如杜预《春秋左传集解》）而非经传原文本身，不得将该注家之说径当作经传明文使用。案例：`E131`（孙叔敖为相与治绩）r23 fix23 补配 `Q235` 时，候选摘录之一是《左传·宣公十一年》"令尹蒍艾獵城沂"（自带系年前598，事目相合），但"蒍艾猎即孙叔敖"一说出自杜预注、另有异说以蒍艾猎为孙叔敖兄弟；最终改取《左传·宣公十二年》士会论楚政"蒍敖為宰，擇楚國之令典"一节——"蒍敖"即孙叔敖（蒍氏名敖）是经传本文用字，无异说之虞。同一纪律亦适用于人物、地望、称谓等一切依赖注家训诂才能成立的事实性认定，凡库内需要"名从主人"式判断处，一律以经传原文可径证者为先，注家异说只作旁证，不得升格为骨架判断的依据。
- **判例（v1.22）·「死者不作亲至」通例**：`event_people.presence` 的语义是「此人当时**身在**事发地」（§6），是为**其人在场**这一行动事实而设的字段；死者非行动主体，即便史文明书其尸身/遗体在事发地，也不构成"在场"意义上的亲至，一律从严标「相关」、`directness` 取 `indirect`。案例出 round23 第二件（时代骨干批）：`E203`（晏婴入哭齐庄公）中庄公之尸有明文「枕尸股而哭」，但庄公已死，标「相关」；`E205`（齐太史书「崔杼弑其君」）中庄公为太史所书之「其君」，同标「相关」。经领队核可，立为通例，此后遇"死者仍在事发地"一类场景一体适用，不再逐案上报。**限定语（v1.23 补，r25 裁定h）：仅适用于史文明书其已卒者**——本通例的适用前提是史文已明书其人身故（如"其君"所指者已遇弑、其尸见哭），死者身份是经传已定之事实，`presence` 字段只是在此前提下补记"死者非行动主体"这一层；**不得反向援引本通例去推定或默认某人已卒**。若某人存殁经传无文（既无已卒之明文，也无未卒之明文），仍应径依 §6「相关＝史文无其在场明文」定级，不必也不应先援引"死者"这一身份——那等于在数据中多断言了一句经传没说的话。案例出 round25b：`E221`（晋灭祁氏、羊舌氏，前514）叔向存殁经传无文，`P_SHUXIANG.death_year_bce` 留空、`summary` 明写"本库不作论定"，`presence` 仍从严标「相关」＋`indirect`，但**不援引**「死者不作亲至」通例（援引即先断其已卒）；两路结论一致而后者不多欠一笔账。
- **判例（v1.25）·「详载中之无」判据用语（r27 裁定13）**：判断"经传对某著名情节是否失载"这一类问题时，若该处经传恰在同一处、同一时段**密集详载相邻或紧邻情节而独缺此一节**，其分量重于一般意义上的"传所不载"（材料本就疏简、各处均少，此时缺载不能说明什么）——本库称此种"于详密之处独缺"为**详载中之无**，是比泛泛"经传无征"更强的排除判据，可与其他证据（如后出文献内部互异）合观以判定某情节属传闻层而非史实骨架。案例出 round27b「鞭平王尸」处置（`E228` 下 `Q377`/`Q378`）：《左传·定公四年》于吴入郢之后详叙「以班處宮」、夫概王与子山争令尹之宫、左司马戌之死、楚昭王涉雎济江入云中遇盗、奔郧、鬬辛止其弟之弑、奔随、随人辞吴等十余节，**独无鞭尸一节**；而《史记》内部三处又互异——《伍子胥列传》作伍子胥一人「掘墓出尸鞭之三百」，《吴太伯世家》作「子胥、伯嚭鞭平王之尸」，鞭者一人抑或二人、掘墓与否、数目有无均不合，益证其为传闻层。本库据此判据、并类推 §11 已裁定的"不为著名但仅见后出层的情节开单独展示位例外"（`E130` 绝缨之宴）之精神，不为鞭尸单立事件，作 `passage` 挂靠既有骨架事件（`E228`），完整可达而不与经传所出者同列于事件时间轴。**判据的适用边界**：仅当确有"同处详载而独缺"这一结构性对照时方可援引；若经传该期材料本身疏简（无从比较"详"与"略"），仍应径依一般的"经传无征"处置，不得泛化套用本判据以强化任一从略结论。**与「异处之抵牾」（v1.27）配为一组，见下**：一为详处之缺，一为异处之牾。
- **判例（v1.27）·「异处之抵牾」判据用语（领队裁定 e，定名经 Sophia 定稿）**：判断后出层（`S`／`T` 及更晚文献）某一情节是否可信时，若经传（`Z`／`G` 层）**于别处另记一事，其人、其年、其事与该情节不能并立**，则此牴触之分量重于一般意义上的"经传无征"——"经传无征"只是未见其事（消极），"异处之抵牾"则是经传正面记下了一件与之冲突的事（积极），与 v1.25 所立「详载中之无」配为一组：**一为详处之缺，一为异处之牾**。案例出 round28b `E272`（吴公子庆忌）：《左传·哀公二十年》明书前475 吴公子庆忌骤谏夫差、出居于艾、遂适楚、请归平越而为吴人所杀，而《吕氏春秋·孝行览·忠廉》（`T010`，见 `Q345`）所载要离刺王子庆忌一事，后世系于阖庐之世（前515 前后），若如此则庆忌当死于是时，上距四十年，两不能并立。**适用边界三条**：① 相抵之一方须是**经传本文**之记载，注家之说不得援引（同本节「注家之说不当经传明文用」判例）；② 本判据只证该后出情节之系年或人物有误，**不得据以径断其事全属子虚**——本库于此类一律"并陈而不论定"（`E272.summary`／`P_QINGJI.notes` 即依此写法，并列三种可能之解而不判）；③ 与「详载中之无」同为**排除性**判据，只可用于降格、分层与存疑，不得用作立事目或升 reliability 的正面依据。（round28b CHANGES 行文中曾拟称"异处之有"，为随手说法，正式定名以本条"异处之抵牾"为准，经 Sophia 定稿。）
- **通例（v1.27）·`sources.url` 体例从实（r28 领队裁定，随批清账）**：`sources.url` 栏须填**实际校核所据之底本**页面（如确以维基文库某卷页核对，则填该页链接），多本互校情况写在 `notes` 中说明（如"据维基文库核对，另以 ctext 互校"），不得填一个未曾核对过的链接充数。**既有条目不回改**——本条例只约束此后新增/修订的条目，不要求普查既有 `sources.url` 逐一核实其是否"从实"。无法确认已核对时（如本轮网络环境不可达）：一律在 `notes` 中如实登记"未核待补"或"环境不可达未验证"，不作断言。起因：round28a／28b 两件 CHANGES 均提请本问题——新源 `url` 依"只填实际所据"之写法（多为维基文库），与既有部分 `Z`／`G` 行历史上填 ctext 页面（甚至出现过"`notes` 说只取到维基文库、`url` 却填 ctext"这一不一致，如 `Z110`）的体例不齐；领队裁定以"从实"为准，不强制回改历史条目，此后新条目一律照此执行。
- **通例（v1.26）·二手引述须标核对状态（r27 追加裁定22）**：本库对**史料**本身早有"无出处不入库"的红线（§7 首条），但对**注文中援引杨伯峻《春秋左传注》、杜预《春秋左传集解》、谭其骧《中国历史地图集》等二手文献**的转述，此前未设同等要求——凡在 `modern_note`／`notes`／`coord_basis` 等注文栏内援引此类二手文献之说，**须同时标明核对状态**：**纸本已核**（注明核对人与日期，如"纸本，站长核对，2026-08-04"）、**电子本转引**（注明所据电子底本，如"以《春秋左传正义》十三经注疏本电子本核出"）、或**未核待补**（加保留语，不作断言语气）。**未核者不得作断言语气**——即不得写成"杨伯峻作某字"这类肯定句式，而须写"任务书/前批引作某字，本库尚未取得原书核对"一类如实的保留表述。**起因案例**：round27a 著录 `Q347` 时径书"杨伯峻《春秋左传注》作『以肄焉』"，而当时本库并未取得杨本原文，是一处未标核对状态、径以断言语气写就的转述——round27b 站长纸本核对后证实该转述结论无误，但**写法本身不合规**，与"史料无出处不入库"是同一类问题只是发生在注文层。Sophia 在 round27c 据此对 r27a／r27b 全部产出作了一次排查，补标 7 条（`Q347`、`Q368`、`Q372`、`E244`、`P_WUYUAN`、`P_SHENBAOXU`、`R276`），其中 `Q372`／`E244`／`R276` 三处并顺带自纠一处引注失实（原写杜预训"復，**報復**也"，经《春秋左传正义》核出杜注原文实为"復，**報也**"，多记一字，结论不变、已订正）。**判据延伸，非新设红线**：本条不要求本库自行遍访纸本核对每一处既有二手引述，只要求**此后新增/修订**的注文引述必须标明核对状态；既有条目在被后续批次触及、顺手核对时补标，不倒查、不溯及既往强制补标全库。**页码引注写法（v1.29 新增，r31 定案）**：注文中引二手文献而附页码者，一律作「**页 N**」（如「页 1534」「页 24–25」），连页用起讫号 `–`，**不作「第 N 页」**。此式自 r30 页码回填件起于全库统一施行，r27c §7 回填示例所用「第 N 页」一式此后不再使用（既有归档文书依 §10.1 不回改）。页码之核对状态并入本条所定之核对状态串，**末缀二式取一**：① 页码系**另一次核对**补入者，作「**，页码 YYYY-MM-DD 补核**」——两个核对日并存，以免读者误以为页码亦出正文核对之日（r30 九处属此）；② 页码与正文用字／落点**同出一次核对**者，作「**，页码同次核**」（r31 四处属此）。不得于二式之外自创第三式；亦不得在只有一次核对时机械照抄第①式，那等于凭空断言存在过一次并不存在的补核动作。**本条关闭 §11 待决之「页码引注串尾九字去留」与「页码写法体例确认」两项。**
- **通例（v1.35 新增，r43b 收官合入·追加裁定 26 核可收录 `docs/changes/r43_zhiben2.md` §12.2 拟文，源出裁定 16、17）·谭图引注体例与两书版次基准**：① **谭图引注统一式**——「《中国历史地图集》第一册·春秋·〔幅名〕幅（页 N–M）」。已知两幅：**郑宋卫＝页 24–25**、**楚吴越＝页 29–30**。幅名以第一册目录为准（**郑宋卫幅之幅名已于 r43 由站长照目录核实；楚吴越幅之幅名尚系沿用 r27c 以来之称谓，未照目录核**）。② **两书版次基准**——杨伯峻《春秋左传注》＝中华书局第 2 版修订本（1990.5 首印；站长所据 2008.7 重印），著录见 `B002`；谭其骧《中国历史地图集》＝中国地图出版社（站长所据 1996.6 重印），著录见 `B003`。全库「页 N」引注一律承此版次——页码自此可核。③ **版本著录行不作来源用**——`B002`／`B003` 只答「所据者何本、页码可核否」一问，**不挂入任何 `source_ids`**，以免以版本著录冒充史料来源。④ **既有引注不回改**——本条设立前之引注照 §10.1 留痕纪律原文保留，就地补一句承接句即可；新出之引注一律照式书写。⑤ **版次著录不改核对状态**——某行补入版次承接句，**不意味着该行所引之书已核**——版次可核与该书已核是两件事（案例见 `E273`／`Q453`：两行只承版次，其「无从核」／「待纸本」之状态一字不动）。**本条与上条「页码引注写法」为同一道防线之两层**：上条管「页码写成什么样」，本条管「页码所据者是哪一版、幅名是否核过目录」。
- **通例（v1.29 新增，r31 立）·判定反转须如实记录，不得抹平**：某点／某条之依据链，若因先前查检有误而发生**反转**（负证改正证，或反之），须在该行注文中**如实记录反转全过程**——原判为何、所据为何、误在何处、何时由谁复核推翻——不得径改写为「一直如此」。理由：**依据链的错误史也是依据链的一部分**；抹平之后，后人无从知晓该判据曾错在哪里、又如何被纠正，更无从判断同型错误是否仍潜伏于他处。**首例**：`places.L_YU`（盂）——r27c（2026-08-04 纸本核对）据**楚吴越幅**报「谭图该幅有睢县而未标『盂』」，据此否定性依据判两个 `certainty` 双双不升级；r30 站长复核**郑宋卫幅**（第一册页 24–25）**实有「盂（唐盂）」落点，在睢县西北**——原「未标」系误查楚吴越幅所致（盂是宋地，本不当于楚吴越幅求之）。r31 据此整段改写 `coord_basis`，`coord` 微调至睢县西北（34.50／115.02，手法照 `L_BOJU` 先例），`coord_certainty` 由 `low` 升 `medium`，`certainty` 经站长授权由 Sophia 判为**维持 `medium` 不升 `high`**（双正证所证者为县域级对应，且不当越过同尺度之 `L_BOJU`）。**并记一处更正**：v1.26 版本记录所立通例「差别不在核对做没做，而在核对到了什么」**通例本身仍立**（本次恰为其又一应验：核对到的是「查错了幅」），惟其**举例**——以 `L_YU` 为「核对到无落点」之例——**已失据，此后不得再以 `L_YU` 为该通例之案例**；归档文书与历史版本记录依 §10.1 不回改，本项更正之正式落点即本版记录。**本条关闭 §11 待决之「`L_YU` 谭图页码待补」项。**（互指：v1.31 新增「提交哈希与运行号一律实测回填，不得预填」通例——史料判定的反转记录与工程记账的预填失守是同一道防线，尺度不因"史料 vs 工程"而两样，见下方「交付体例·实测口径」节。）**条件关闭之留痕，与判定反转之留痕同例（v1.34 新增，r43）**：解悬／落定时写下的**回退条件**，若日后经复核而关闭（反证不成立），其文字照留不删，只在其后注明「已由某裁定关闭」——写下过的岔路不因未走而抹去，与本条同一道防线。首例：`Q443`（婢案回退条件，经追加裁定 21 关闭）。

### 交付体例·实测口径（v1.31 新增，r38 立）

本节此前并无归拢：交付文档的命名规则（下方）只管"文件叫什么"，不管"文件里的核验类数字从哪来"；上方各条「二手引述须标核对状态」「判定反转须如实记录，不得抹平」管的是**史料**注文的核对纪律，未曾覆盖交付文档**自身**（提交、部署、复验一类表格）里同样存在的实测/推断之辨。本轮据 Vision r37 自曝一例首次触及此处空白，就近立目如下。

- **通例（r38 立，源出 `docs/delivery_vision_r37.md` §十.0，Vision 自曝留痕）·提交哈希与 Actions 运行号一律待动作完成后实测回填，不得预填**：交付文档「提交」「生产」一类表格栏目中的 git 提交哈希与 GitHub Actions 运行号，只允许在对应的 `git commit`／`git push`／Actions 运行**实际发生之后**、以实测手段（`git log`、`gh run list`、`gh run view` 等核验所得）回填；不得在动作尚未发生前，按预期或惯例先填一个"届时应当是"的占位值——即便打算随后再提交一次订正也不许预填在先。理由：读者面对一份表格，无法分辨哪一格是真实核验所得、哪一格是预先估计，而这一栏又是全表最容易蒙混过关的——两个数字长得和其余实测字段毫无二致，读者默认它们必是从 `git`／`gh` 实际输出中抄来，不会想到是"预先估计"。**病例**：`docs/delivery_vision_r37.md` §十.0——Vision 在回填该文交付表格「追记提交」一栏时，先填了 `0a9f1ef` 与 Actions `31976886766` 两个当时尚不存在、按预期先填的值；提交推送后实际得到的是 `6fa1851`／`31976930936`，与预填值全不相符，随即以"二次追记"一行订正，且**原样留痕未抹平**（未把原失误静默改掉，而是新立 §十.0 一段专记此事）。**为何要立此条**：本库交付文档体例通篇以「实测不是推断」自律（该文件 §四、§六、§十各处均以此语自律），预填哈希/运行号正是这条自律里最隐蔽的一处失守——用推断冒充了实测。**互指**：与 §7 v1.29 通例「判定反转须如实记录，不得抹平」（依据链的错误史也是依据链的一部分）同一道防线，彼条管史料判定的反转记录，本条管工程记账的预填失守，尺度不因领域而两样。**生效范围**：本条自本版起对全体角色的交付文档一体生效，含本文件自身之交付说明（`docs/delivery_skipper_r38.md`）——即本条一经写入，第一个必须照此实测回填的交付文档就是记录本次改动的那一份。**边界（v1.32 新增，r39 补，源出 `docs/delivery_vision_r38.md` §六／§七 Vision 首例实做及自曝疑点）·回填链截断于追记提交**：上条要求"实测回填、不得预填"，但未言明回填动作**自身**——它也是一次提交、也触发一次 Actions——是否也须再入表回填；若逐次都要求"回填了就再回填一次"，则永无终点。裁定：**回填链截断于追记提交；收尾提交之运行号口头上报、不入表。**即交付表格只需完整记录到"补齐哈希与运行号的那一次追记提交"为止——该追记提交自身的哈希与运行号仍须照旧实测回填入表；此后若还有一个仅用于确认"追记提交已成功部署"的收尾提交，其自身的哈希与运行号不再要求入表，改为口头向领队上报即可。**理由**：**档案完备以可核为界，其后链条由仓库自证**——交付文档入表的意义在于让读者拿着这一格数字去仓库核对；而回填之后的每一次提交，本身已经完整记在 git 提交历史与 Actions 运行记录里，任何人随时可 `git log`／`gh run list` 自行追溯到底，文档没有必要、也不可能对这条链条做穷举式的登记——登记的义务止于"把读者引导到可核实的起点"，起点之后的链条本身即是自己的证据。**首例**：`docs/delivery_vision_r38.md` §六——该件回填到追记提交 `d238728`（Actions `31978021663`）为止入表，其后的收尾提交（实为 `be87d6e`）之运行号未入表，按本条应作口头上报处理；本条即据该件 §七 主动提请、由站长裁定正式确认为通例。

各角色每轮工作结束后的交付说明，统一存于 `docs/`，命名格式：

```
delivery_<agent>_r<团队轮次>[a|b].md
```

- `<agent>`：角色小写英文名（如 `skipper`、`sophia`、`vision`）。
- `<团队轮次>`：团队协作的整体轮次编号（纯数字，不加前导零）。
- `[a|b]`：可选后缀，仅当同一轮次内该角色产出多份交付文档需要区分先后/子任务时使用。
- 示例：`delivery_skipper_r7.md`、`delivery_sophia_r7a.md`、`delivery_sophia_r7b.md`。

**旧文件不改名**：本规范生效前已存在的交付文档（如 `docs/delivery_vision_round4.md`、`docs/delivery_skipper_round1.md` 等 `round<N>` 命名）保留原名，不做迁移；仅自本规范生效起的新交付文档按上述格式命名。

## 9. 前端本地存储与外部资源例外（v1.7）

站点定位是纯静态展示，此前一律不落地任何浏览器本地存储、不引入站外脚本/资源。r13/r14 起出现实际需求（首访引导需记忆、访问统计需官方 beacon），本节明确解禁范围，避免"能不能用"每次临时判断。

### 9.1 localStorage 解禁范围

允许使用 `localStorage`，但**仅限**以下两类用途，超出即视为违规：

1. **首访标记类**：一次性提示/引导是否已看过（如首访三步引导 `TOUR_KEY`），只存布尔/字符串标记，不存用户输入内容或可识别个人信息。
2. **界面偏好类**：纯展示层的用户选择记忆（如列表/地图视图切换偏好、某折叠面板的展开状态），刷新后免于用户重新操作一次，不影响数据正确性。

**明确禁止**：不得用 localStorage 存放数据表内容或其缓存（数据以 `site/data/*.json` 为唯一运行时来源，避免本地缓存与线上数据不一致）、不得存放可识别用户身份的信息、不得用作分析/埋点的自建载体（埋点需求走 9.2 的官方 CF Analytics beacon，不自制）。

**读写规约**：所有 localStorage 读写必须包一层 `try/catch`（隐私模式/存储禁用下 `localStorage` 可能抛错），失败时静默降级为"当次会话不记忆"，不得让页面因此报错或白屏。参见 `site/app.js` 的 `tourSeen()`/`tourMarkSeen()` 写法。

## 10. 协作节奏：备料与合入分离（v1.7）

自 round9 起团队实践稳定为"备料"与"合入"两个独立动作，本节成文固化，避免新人/新 agent 误以为交付即生效：

- **备料（Sophia）**：史料增量一律先落 `data/incoming/round<N>/`（含 `*_new.csv` 与 `CHANGES.md`），并在临时副本上完成"合并模拟"（拷贝主表 → append 全部增量 → 跑 `tools/validate.py` → 确认 exit 0），但**不动 `data/csv/` 主表**。合并模拟通过只代表"这批数据本身自洽、可合入"，不代表"已经合入"。
- **合入（Skipper）**：收到备料后按 `CHANGES.md` 逐条比对执行，真正把增量写入 `data/csv/`，重跑 `tools/csv_to_json.py` 生成 `site/data/*.json`，`tools/validate.py` 再过一遍，一并提交。合入者对史料判断没有自由裁量权——落实不了或存疑一律停下报告，不得自行改动史料口径来"让它能合"。
- **两者可以跨轮次错开**：备料完成不代表下一轮必须合入（round13 楚秦线即为一例：v1.7 成文时该批已备料完成但暂不合入，v1.9 随 fix13 一并正式合入，见 `data/incoming/round13/CHANGES.md`），是否合入、何时合入由领队按整体节奏排期决定，`data/incoming/` 下的目录可以合法地"等待"多轮。
- **合入前置条件的显式化**：若某批增量依赖尚未落地的基础设施（如本轮楚秦线的雍/郢坐标依赖底图西扩，见 `docs/map_expansion_plan.md`），该依赖必须在 `CHANGES.md` 中显式注明，合入者据此判断是否具备合入条件，不得"先合数据、坐标留空将来再补"之外的隐性依赖被忽略。

### 10.1 CHANGES.md 归档纪律（v1.17）

`data/incoming/round<N>/` 合入完成后按惯例即清空删除，但 `CHANGES.md` 本身承载的是史料研究员的论证过程（考据取舍、presence 判据、待复核项等），并非只是"待办清单"，一旦随目录清空而未留痕，论证过程即永久丢失、无法从 `data/csv/` 的最终结果反推。为此明确：

- **归档动作与时机**：合入者（Skipper）在清空 `data/incoming/round<N>/` **之前**，必须先将该目录下各件 `CHANGES.md` **原样**（不重排、不摘要、不改写、不合并多件为一件）复制归档至 `docs/changes/rXX_<批名>.md`，与本轮合入的数据改动、生成物一并提交入库。顺序固定为：合入 `data/csv/` → `csv_to_json.py` 重新生成 → `validate.py` 通过 → **归档 CHANGES.md 至 `docs/changes/`** → 清空 `data/incoming/round<N>/` → 一并提交；清空动作不得早于归档提交完成。
- **命名规则**：`docs/changes/rXX_<批名>.md`，`rXX` 为团队轮次编号（与交付文档同口径），`<批名>` 取该批任务书中的代号（如同一轮次并行两批，各批各自归档一份，如 `r21_songxiang.md`、`r21_xiaji.md`），不得合并改写为一份"综述"。
- **教训记录（本规则起因）**：r21（宋襄公升格线 + 夏姬线）两件备料合入后，`data/incoming/round21/` 被直接清空，两件 `CHANGES.md` 从未提交入库，git 历史中亦无任何记录；其中 Sophia 在夏姬件 `CHANGES.md` §0.7 所写的 presence 逐点核订论证（含书法反证）随之丢失，事后只能靠续接 Sophia 当时的会话追回部分内容，无法从 `data/csv/` 结果或交付说明完整还原原始论证。
- **r21 归档缺口——已回补（v1.18 更新，原 v1.17 记为待回补）**：夏姬件核订论证由 Sophia 落盘为 `docs/delivery_sophia_r21.md`（198 行，两线论证俱全，含 §0.7 presence 逐点核订与书法反证）；宋襄件由**执行 r21 合入的那次 Skipper 会话**从其自身上下文原样追回，落盘为 `docs/changes/r21_songxiang.md`，该会话核对后报「未发现已佚部分」，宋襄件 `CHANGES.md` 全部实质内容已逐字取出。两份文件均已入库，v1.17 记录的"宋襄件论证缺口未回补"结论至此解除。此后一律先归档、后清空，避免同类史料论证再度永久失传。

### 10.2 有界扫描的留痕纪律（v1.29 新增，r31 立）

凡任务书划定范围令「逐一对照」者（如「落于某图幅范围内的低置信地点」），**对照结果须完整留痕，不得只列有改动者**：查过而未动的条目同样逐条列入该批 `CHANGES.md`，并注明未动之由（**不在范围** ／ **范围内但本库无新证** ／ **本轮无从核**）。理由有二：① 下一轮不必重查；② 使「查过」与「没查」事后可分辨——r27c 之误（据错幅报「未标」，并据以立判据）正因「究竟查的是哪一幅」未曾留痕，直至 r30 因页码对不上才暴露。

**自限一条**：备料者本人无纸本／可靠电子本者，一律记「**本轮无从核**」，**不得以推理代核对**，尤不得写成「查无落点」——那是把消极的「没查到」写成积极的「不存在」，与 §7 v1.26「二手引述须标核对状态、未核者不得作断言语气」是同一道防线。范围边界不明者（如某点是否落在该幅图面之内）另标「幅界存疑」，一并留痕待核。**首例**：r31 郑宋卫幅有界扫描，50 点全集分四组尽列（甲组 23 点在幅、改 2 不动 21，乙组 27 点不在幅只记不动），并留下 21 点的现成待核清单。
