### 6.1 拟增条文全文（附于 §7，**紧随 v1.39「竹简书不称『正文』」条之后**）

> - **体例（v 升下一号 新增，r44d 立，据 2026-09-02 站长二裁〔图版核定〕）·简上之符可入 `quote_original`；其归属之判据在图版，不在释文页**：

## 8. 通行字转换规则之可行性——**实况回报（规则须改，非数据须改）**

任务书所拟之纯前端规则为「**括注取括号内、「X＝（Y）」取 Y、光板照旧**」。本件以合并模拟内之探针**实测**（`sim_fix44d.py` §6，四条断言全过），结论**二则不成立、须补**：

**⚠ 其一：「X＝（Y）取 Y」之式于「賽＝爲＝（息媯）」不成立**——该处是**二隶定字各带一「＝」、共对一个双字括注**（`X＝Z＝（YY）`），非「一字＋＝＋括注」。以任务书字面之式（一字＋括注）施之，实测得

> 蔡哀侯取妻於陳，**賽＝**息侯亦取妻於陳，是**賽＝爲＝**息媯……

——括注被剥而「賽＝」「爲＝」原样留在通行字视图里，**读者见到的比不转换更糟**。**可行之式**：把「隶定字＋＝」当作**可重复之前缀单元**一并吃掉，即

```js
const RULE = /(?:[㐀-鿿]＝)*[㐀-鿿]?（([^）]+)）/g;  // 替换为 $1
```

实测：`Q442` 得「蔡哀侯取妻於陳，息侯亦取妻於陳，是息媯。……息侯弗順，乃使人于楚文王……」；`Q448` 得「立六年，秦公率師與惠公戰于韓……」——**俱与站长所欲之「是息妫」相合**。（末段之 `[㐀-鿿]?` 一字为可选，正是为兼容「賽＝（息）」这类**无裸隶定字**之形；若写成必选，则会误吃括注前之一个正文字。）

**⚠ 其二：规则不限域则会破坏传世层之引文**——`Q167`（《史记》层，`quote_type` 后出叙事）之 `quote_original` 含「殺悼子**（卓子）**」，此括注是**本库所加之异名注**，不是丙档括注式。规则若全库通施，实测得

> 獻公卒……里克……殺奚齊……又殺**悼卓子**……

——**一处真实的文本损坏**。**故转换须限域**：只施于**丙档括注式之引文**。可用之判据二（择一或并用，属 Vision 与领队之事，本库只报事实）：㈠ `quote_type === "出土文献"`（现网实测：`quote_original` 含全角括注者全库仅三行——`Q167`／`Q442`／`Q448`，其中 J 层二行、`Q167` 为 S 层）；㈡ 层标增句含「丙档·照录括注式」一语（`Q442`／`Q448` 俱有，`Q167` 无），**判据更准且随体例自动生效**，本库倾向㈡，但不代裁。

**其三（只是界，不是错）**：现行数据中「＝」**必与括注同现**；若他日入库一处**裸「＝」**（简上有符而整理本未出括注），上式将原样留下该符。届时须另定其显示（隐去、或以浅色小字保留），**本库建议不预写规则，待首例实到再定**——同「未核即不代填」之则。

**本库对本节之自限**：以上皆**数据侧之静态实测**（Python 正则等价施于现网同形之字符串），**未启浏览器**；字形覆盖、窄屏换行、悬停切换之交互，仍属 Vision 任务 9 实测，本件不代断（此即 fix44c §7.1 乙所留之界，**至今未销**）。

**一句结论**：**规则的事，不是数据的事**——所录之形不为迁就前端而改；本节所报是「规则须补两处」，非「形须改」。

## 12. 附注区（写作向／不入公开数据）

- 一个「＝」，来回三件才落到纸上：先是不知它是谁写的，再是知道了却不知它作什么用，最后我们决定——**不知道它作什么用，也照抄下来**。这大概就是校勘与创作最不同的地方：写小说要先懂了才落笔，做校勘是**先照原样留住，懂不懂另说**。留住了，后人才有得懂。
- 息妫这一句现在读起来是「郶（蔡）哀侯取妻於陳，賽＝（息）侯亦取妻於陳，是賽＝爲＝（息媯）」。写她的人物页时可用作一个暗扣：**她在竹简上的名字，写作「賽爲」，二字旁各带一个小小的符号**；那两笔是两千三百年前一个楚地书手落笔时所画——**画的人是谁已经知道了（简上书手），画它作什么用还没定**。我们今天为了「那两笔到底是谁画的」，翻了两轮图版。
- 「照录者录其形，不待其读定」——此语可入日后「考据是怎么做的」一篇之骨。
