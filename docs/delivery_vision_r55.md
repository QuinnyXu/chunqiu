## 二、何以如此落（三处工程判断，请过目）

### 1. 自验之物写成**选择器**，不写成 id 清单

`BASE_MAP_NEEDS` 之值是 `"#layer-states ellipse[data-state]"` 之属，不是 `"layer-states"`。**一式兼验其 id 与其属性之形**：若后人把 `data-state` 改名而 id 照旧，id 清单一式会报绿，而热区已全失。
★ 并有一利：**所缺者原文照报**，故告文自带所缺之 id，**不须另备一份「id → 人话」之映射去跟它同步**——少一处会走样的账。

### 2. `viewBox` 亦入自验

裁九十九③ 所列三物（外层 svg／`#layer-anchors`／海报化之节点）我**逐一落了**，另**自加一条 `viewBox`**。其由：`MAP_W`／`MAP_H` 与 `project()` 之投影常数与底图 `viewBox` **同源而无一处相连**——底图若换了 viewBox，**所有落点整体偏移，而没有一行代码会报错**。这正是裁九十九 所治之「坏而不声」之同类，故一并入册。★ **若领队以为此条逾命，可单条撤之（删 `mountBaseMap` 内 viewBox 一段即可），其余不动。**

### 3. 告之样式写成**内联**，不入 `styles.css`

本件之界不含 `site/styles.css`，故 `.base-map-breach` 之式以 `style.cssText` 内联写之，**取现成之令牌**（`var(--cinnabar)` 朱砂／`var(--silk-panel)` 绢帛／`var(--serif)`）——**未新造一个色、未动色彩两级制**，故 `design_notes` 不须升号。
★ **候裁（只报不办）**：若领队以为当归 `styles.css` 之 `.base-map-breach` 一则，是一行搬迁之事，我不自行越界去办。
★ 站内无暗色模式（实核 `styles.css` 内 `prefers-color-scheme`／`data-theme` **0 处**），故无双主题之虑。

## 三、★ 自勘与反转（**原文照录，不抹平**）

### 【实测反转·一】旧版之坏不是「抛错」，而是**错被吞掉＋一句张冠李戴之告**

**原断言之文（走查门初稿，照录不删）**：
> `oldThrows: true` ——「**旧版另抛未捕获之错（pageerror ≥ 1）**，页内一字不告」

**其言不实，首跑四条俱红。** 实读其由，并以诊断本实测，得其真相——**旧版之坏分两态**：

| 态 | 实测（旧版 `f611b81`，底图删去 `#layer-anchors`） |
|---|---|
| **深链入站**（首载即在 `#/p/P_WENJIANG/map`） | 其错落在 `boot()` 之内，被 `site/app.js` 文末 **`boot().catch(...)` 吞掉**——**pageerror 为 0**；其唯一之声在**页脚**，且**张冠李戴**：「**加载失败：Cannot read properties of null (reading 'appendChild')（请经 http 访问并确认已运行 tools/csv_to_json.py）**」——**指向数据管线与 http 访问，而病在底图**；且其位在页脚，图之处一字不告 |
| **站内导航**（自首页点入，经 hashchange → `render()`，已出 `boot()` 之外） | **抛未捕获之 TypeError**（`appendChild` of null），页内仍一字不告 |

★ **故「坏而不声」比裁九十九 所书更坏一层：它不只是不声，还会指错方向。** 一个照那句页脚去查的人，会去重跑 `csv_to_json.py`、会去换服务器——**而病在一枚 id。**
★ **其源码证据已入走查门【契·庚】一条**（`boot().catch` 之文确含「请经 http 访问并确认已运行 tools/csv_to_json.py」），不是口说。
★ **走查门遂改为二途俱量**（`nav: "deeplink" | "insession"`），逐态书其所期：**一个只量深链的门会把旧版之抛错整个漏掉；一个只量站内导航的门会把那句误导之告整个漏掉。**
★ **新版二态俱一样**：pageerror 0、图框内一枚 `role=alert` 之告、**页脚未被污**（走查门另立一条断之：新版页脚不含「加载失败：」）。

### 【门内自撞·一】【契·己】之量法把我自己写的注文数进去了

首跑【契·己】红：量法作 `innerHTML = baseMapText` 之计数，**期三而得四——第四个出自我自己写进 `app.js` 头清册之注文**。
★ **错在量具，不在被量之物**。改量法为 `.innerHTML = baseMapText;`（带点带分号＝代码之形），**不改断言之期以凑绿**；并于门内把裸式之计数一并打印出来（今为 4），**使后人见其分**。
（此与 r54「标签与所量之物不符即是假账」同族；记忆所存「QA 基础设施诚实优先」之例又添一笔。）

### 【门内自撞·二】「其告确在页面上现形」之判据取错了对象

次跑于「丙式·375px·站内导航·人物地图」一格红：量法作 `notes.every(可见)`，而该格之告**有二枚**——先落首页（`viewBox` 之变即告一枚于 `#home-map`），再导航入人物地图（又告一枚）；**首页之告随其视图隐去而不可见，遂把「皆可见」撞红。**
★ **红的是量法，不是被量之物**：此格之真相是「本页之告可见、上一视图之遗留不可见」，二者俱属应然。
