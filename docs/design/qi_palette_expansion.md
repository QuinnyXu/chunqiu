## 0. 摘要

| 问题 | 结论 |
|---|---|
| 齐系第七位（晏婴）在现判据下有解吗 | **数学上非空、视觉上为空**：可行解 2925 个，但灰阶全部 ≤20，暗于站点正文玄墨（灰阶 42），在卡顶条/轨迹/徽记上一律读作黑 |
| 亮端天花板是「白字」造成的吗 | **不是**。对绢帛 3.5 在灰阶 124 破线、对白 4.1 在灰阶 126 破线，两条判据几乎同点触顶。改掉子导航白字**换不来 2 阶** |
| 每族的绝对容量上限 | 灰度通道 `floor((124−g_min)/13)+1`：g_min=33 时 **8 人/族**，g_min=40 时 7 人。**色相分支不提高此上限** |
| 推荐序 | **c（形状/纹理承担）> a（重排）> b（族内扩谱）**，理由见 §6 |
| 郑系第五阶（子产） | **有解，且不必重排**。推荐 `#1D3840`（灰阶 52，青相），跨族最紧 ΔE76 15.13、族内最小 Δ灰阶 15；取此值后郑系仍余第六阶（灰阶 36–39） |

一句话：**齐系的困境不是「选不出色」，是「灰阶轴用完了」**——而灰阶轴是色盲/灰度双通道原则的物理载体，任何色相层面的花招都绕不过它。

## 1. 口径与方法

### 1.1 判据（沿用 design_notes §2.1，四条）

| # | 判据 | 阈值 | 来源 |
|---|---|---|---|
| 1 | 族内相邻 Δ灰阶 | ≥13 | 色盲双通道底线 |
| 2 | 人物×人物 ΔE76 | ≥13.2 | 库内既有跨族最紧一对（鲁庄公×晋文公）为基准线 |
| 3 | 对白 WCAG | ≥4.1 | `.person-nav button[aria-current="true"]` 主题色底白字 |
| 4 | 对绢帛 WCAG | ≥3.5 | 现库最低档（武姜 3.54） |

灰阶＝sRGB→线性→WCAG 相对亮度 Y→回伽马×255；ΔE76 取 CIE Lab（D65/2°）。与 design_notes 口径一致。

### 1.2 ⚠ 判据 2 的口径实测偏差（**须领队确认，影响全部结论**）

design_notes §2.1 把判据 2 写作「**人物×人物** ΔE76 ≥13.2」，字面读作对同族亦生效。**实测：库内现有 6 对同族相邻低于 13.2。**

| 族 | 相邻对 | Δ灰阶 | ΔE76 |
|---|---|---|---|
| 齐 | 文姜 × 管仲 | 14 | **5.67** |
| 鲁 | 鲁桓公 × 鲁隐公 | 16 | **7.99** |
| 齐 | 齐桓公 × 齐僖公 | 16 | **9.09** |
| 齐 | 齐僖公 × 文姜 | 17 | **9.81** |
| 楚 | 楚庄王 × 息妫 | 23 | **10.28** |
| 卫 | 宣姜 × 庄姜 | 27 | **12.00** |

全库最紧一对实为 **齐·管仲 × 齐·文姜 ΔE76 5.67**，不是 design_notes 记载的「鲁庄公×晋文公 13.2」——后者是**跨族**最紧对。

**即库内实际执行的是双判据分工：同族靠 Δ灰阶≥13，跨族靠 ΔE76≥13.2。** 这是合理的（同族本就同色相，靠明暗分阶；ΔE76 在同相内天然偏小），但书面规范未写明，导致本轮调研初期两种口径给出的容量结论相差一倍。本文档一律按**实际执行口径**计算，并建议 design_notes 补一句订正。

> 这不是数据错误，是措辞未分族别。r22 三色（鲍叔牙 17.6／曹刿 17.0／介之推 18.3）报的是「对全库最紧」，恰好都同时满足两种口径，故未暴露分歧。

### 1.3 色值源与复现

色值取自 `site/styles.css` `:root`（r23 现值，26 人 + 9 族基色 + 6 功能色）。核心计算为**全 sRGB 立方体 16,777,216 色逐一枚举**（numpy 向量化分块，非采样）。自包含复现脚本见**附录 A**，跑法 `python verify_all.py`，仅需标准库。

### 3.3 影响面与工作量（实测）

- **代码影响面：`site/styles.css` 六行**。`grep` 全仓核验：齐系六色值仅出现在 `styles.css` 的 `--p-*` 定义处，`site/assets/` **零命中**（徽记 SVG 用 `currentColor`），`app.js` 由 `resolveProtoColors()` 单点读取、不写死色值。
- **对其余 20 人：零影响。** 新色对跨族最紧 ΔE76 13.2–18.6，均不低于基准线，无连锁重排。
- **分享卡：零影响。** r22 起色签按国色家族计（用 `--state-*`），人色不参与。
- **工作量估计：改 6 行 CSS + 更新 design_notes §2 色值总表 + QA 截图复验（选人页/子导航/时间线/地图/关系全景五处）≈ 半个工作单元。** 工程量不是这条路的成本，认知成本才是。
- **真正的代价**：管仲（r20 上线）与文姜（初代主角）位移超过 10，读者会读作「换了一个人的颜色」；文姜是站内最早、最有辨识度的主角之一。

**体例问题**：郑的「青—绿双相」与鲁的「赭黄向黄扩谱」都是**纯视觉分相**，不承载语义。齐若分「公室／卿臣」，是第一次让色相携带身份含义——那么管仲、鲍叔牙（皆卿臣）理应迁入卿臣支，**这就等于路线 a 的部分重排**，两条路的成本在此合流。

## 5. 路线 c —— 纹理/形状承担增量，色彩容量封顶

### 5.1 立论

design_notes §2 已写明：「**徽记形状恒定不变，作个人辨识第一锚点、不随色改**」。路线 c 不是新发明，是**把这句话执行到底**——承认色彩是第二通道，容量封顶后由第一通道兜底。

现有先例三条，皆已上线：并观双轨「甲＝圆点＋实虚线／乙＝方点＋点划线」（形状＋纹理双冗余，§6.6）；每个人物页恒在的 24px 徽记；关系全景节点内嵌徽记。

### 5.2 容量

- **色彩通道**：封顶 6 色（齐系现状，零改动）。
- **形状通道**：现库 26 枚徽记形各异，已实证可承载 ≥26 个可分实体。

- 灰阶 54 虽保留最多第六阶余量，但距郑庄公恰为 13、**卡在判据线上**，灰阶计算含取整，无容差；52 给出 Δ15，有余量而不浪费。

def hex2rgb(h): h = h.lstrip("#"); return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))
def rgb2hex(r, g, b): return "#%02X%02X%02X" % (r, g, b)
def _lin(c): c /= 255.0; return c/12.92 if c <= 0.04045 else ((c+0.055)/1.055)**2.4
def _gam(c): return 12.92*c if c <= 0.0031308 else 1.055*(c**(1/2.4))-0.055
def lum(h): r, g, b = hex2rgb(h); return .2126*_lin(r)+.7152*_lin(g)+.0722*_lin(b)
def gray(h): return round(_gam(lum(h))*255)
def contrast(a, b):
    x, y = lum(a), lum(b)
    if x < y: x, y = y, x
    return (x+.05)/(y+.05)
def hue(h):
    r, g, b = [c/255 for c in hex2rgb(h)]; mx, mn = max(r, g, b), min(r, g, b); d = mx-mn
    if d == 0: return 0.0
    if mx == r: v = ((g-b)/d) % 6
    elif mx == g: v = (b-r)/d+2
    else: v = (r-g)/d+4
    return v*60
def sat(h):
    r, g, b = [c/255 for c in hex2rgb(h)]; mx, mn = max(r, g, b), min(r, g, b)
    if mx == mn: return 0.0
    L = (mx+mn)/2; d = mx-mn
    return d/(2-mx-mn) if L > .5 else d/(mx+mn)
def lab(h):
    M = ((.4124564,.3575761,.1804375), (.2126729,.7151522,.0721750), (.0193339,.1191920,.9503041))
    WP = (.95047, 1.0, 1.08883)
    c = [_lin(v) for v in hex2rgb(h)]

    return (116*f[1]-16, 500*(f[0]-f[1]), 200*(f[1]-f[2]))
def de76(a, b):
    x, y = lab(a), lab(b)
    return (sum((x[i]-y[i])**2 for i in range(3)))**.5
